> 目标：把真机 PLC 程序（`cnc.lad` / `cnc_1.lad`）里**每一个并联块**逆向还原成网络树，
> 再重新生成，再解码比对 —— 用全量数据而不是几个样本来证明编解码是对的。
>
> 复跑：`python roundtrip_full.py`（约 5 秒）

## 二、结果

|---|---|---|
| 结构往返一致 | **1187 / 1187** | 解码出的树 == 重新生成后再解码出的树（串联/并联/嵌套/元件参数全同） |

**结论：结构层面已经做到 100%。** 剩下 410 条 rung 的「几何/字节」差异不属于编解码错误，

## 三、这轮验证改掉的 5 个认知错误

全量数据比样本更狠：样本上"看着对"的规则，在 1188 条 rung 上会立刻露馅。

### 1. 并联分支是**左对齐**，不是右对齐

之前的样本（`B_branch.lad`、`cnc_1.lad` R25–R29）恰好都画成"末端贴住汇合竖线"，
于是得出"右对齐、短分支左边留空"。全量统计推翻了它：

```
左对齐 282 条 / 右对齐 65 条 / 两者不同 78 条 / 恰好相同 49 条
```

正确规则：**各分支从块左边界起排，短分支用 `0x0d` 横线从"最后一个元件的右边缘"补到汇合点；
元件前面的空白保持 `0x00`（不画线，但同样导通）。**

### 2. 汇合竖线只跨到"最后一个分支所在行"

并联块里的分支是**靠上对齐**的：长分支多出来的行是死端。

```
R119  分支1 = (I86 | I100) → I2049        ← 占 2 行，输出在第 1 行
R120  分支2 = I56 → I2049 → I2452 → C5866 ← 1 行
```

汇合竖线只到第 1 行，第 2 行（`I100` 那一行）后面必须全 `0x00`。
最初按"整个块高"画线，结果把 `I100` 的横线补到了汇合点，**直接把触点旁路了** ——
结构往返立刻报"未能约简为串并联"。同理，只有"分支输出行"才需要横线补齐，
分支内部的死端行一律不能补。

### 3. 串联里各部件行数**可以不同**

`(A|B) then (C|D|E)` —— 2 行对 3 行，早期版本直接报错。真实程序里这很常见：
一律**靠上对齐**，行数少的部件占前几行，下面的行留给行数多的部件，
两个并联块的竖线在同一列边界上会自然拼成一条连续线。

### 4. 分支的上下顺序会被"归并顺序"打乱

串并联约简时"先合并哪两条边"由图的遍历顺序决定，与视觉顺序无关。
若摊平嵌套时按归并顺序拼接，3 个分支会排成 0,2,1（`cnc_1.lad` R15–R19 实测）。
必须**按行号重新排序后再摊平** —— 而且不能"先摊平再排序"，因为整棵子树会带着它的
最小行号一起挤到前面去。

### 5. 一条 rung 可以高到 59 行

`cnc_1.lad` R941–R999 是一条 **59 行 / 52 分支**的大并联。原来设的 32 行上限把它挡掉了，
现改为 64 行。

## 四、为什么"逐字节 100%"做不到

新代 PLC 编辑器**不做自动排版**：元件放在第几列、哪里插一条横线、右边补几格留白，
全部由人决定。同一个逻辑（例如 `I100 串 (I101|I102)` 驱动 `O200`）可以画成很多种合法布局，
每一种编辑器的 AutoFix 都接受。

所以"任意文件重新排版后逐字节相同"在原理上不成立 —— 信息不在文件里，在画图人的手上。

剩下的 410 条差异，抽检后全部属于这三类：

| 类型 | 例子 |
|---|---|
| 分支上下顺序不同（逻辑等价） | 3 分支并联，原件按 A,B,C 排，生成按 A,C,B（已修：按行号重排后再摊平） |
| 汇合竖线前面多/少一格 `0x0d` | 原件 `…0d 02 0d 08 <线圈>`，生成 `…0d 02 08 <线圈>` |
| 单元素行靠左/靠右不同 | 原件 `END` 在 col0，生成靠右到 col9（已修：`left_anchor` 保留原始对齐） |

因此工具的策略是**分层验证 + 无损回写**：

- 能完整复现的行 → 复现，逐字节相同；
- 不能复现的行 → **保持原样字节，不做有损重排**。

## 五、读能力（本轮新增）

`roundtrip_full.py` 验证的是"解码器 + 编码器"是否互逆；这轮同时把它变成了产品能力。

| 模块 | 作用 |
|---|---|
| `syntec_parse.py` | `.lad` → 网格 → **网络树**（端子图 + 串并联约简） |
| `syntec_read.py` | 网络树 → 元件列表（与 `add_rung` 同格式）+ 整文件读取 + 保留记录 |
| `syntec_model.py` | 新增 `raw` / `contact_t` / `contact_c` / `jmp` / `msg` 元件，支持原样回写 |

MCP 新增三个工具：

- `read_ladder` —— 只读解析，返回带竖线的梯形图文本 + 每行的元件列表（JSON）；
- `load_lad` —— 读入工程，可继续 `add_rung` / `save`；
- `dump_rungs` —— 把当前工程导出成元件列表。

**关键特性：读入 → 原样保存，逐字节相同。**

```
cnc.lad    87042 字节 -> 526 条 rung，可编辑 309，锁定原样 217，存回逐字节相同 ✓
cnc_1.lad  99402 字节 -> 602 条 rung，可编辑 366，锁定原样 236，存回逐字节相同 ✓
```

做法：`load_lad` 对每一条 rung 先试着用语义模型重新生成并比对字节，
一致才转成可编辑元件；不一致（人工排版）就锁定为原始字节。
批注行 / 版本记录 / 设备变量注释也按"它前面有几条逻辑行"原位保留。

于是"让 AI 改一段、其余一个字节不动"这件事成立了。
