# syntec-plc 技能说明

> 版本 **1.13.1** · 主文件 + 参考资料约 4100 行 · 面向新代（SYNTEC）CNC 的 `.lad` 梯形图编写与审查
>
> 这份文档是给人看的说明书：技能里有什么、每个文件管什么、什么时候翻哪一份。
> 给模型看的执行指令在 `SKILL.md`，两者不重复。

---

## 1. 它解决什么问题

新代 PLC 编程有三个不在手册里的坑，这个技能就是为了绕开它们：

| 坑 | 后果 | 技能怎么处理 |
|---|---|---|
| `.lad` **没有文件头、没有校验和** | 字段错一位，编辑器不报错，只显示一张错的图；到现场才炸 | 所有读写走解码器，不手拼字节；`check_lad.py` 做字节体检 |
| 注释块固定 **cp950 繁体** | 简体写进去不报错，显示成问号或整段被吞 | `zh_tw.py` 转换 + `set_comment` 直接管短/长批注 |
| 手册只讲元件，**不讲程序怎么组织** | 每个人按自己习惯排地址、报警、手自动，交接即失控 | 从四台真机反推现场约定（`project-conventions.md`） |

三种典型用法：

- **从零写**：给工艺要求 → 出 I/O 表 → 出 `.lad` → 三层验证
- **改别人的**：读入现有 `.lad` → 反推意图 → 定点改 → 报告影响面
- **审查**：查双线圈、点位冲突、互锁缺失、报警不自锁

它**不能**直接写控制器。上机流程永远是：生成 → 编辑器打开核对 → 人工确认 →
拷到 `DiskC\OpenCNC\Ladder\cnc.lad` → 重启加载。

## 2. 文件地图：十二个文件，各管一段

1 个主文件 + 7 份参考资料 + 2 个脚本 + 1 个模板。

```
syntec-plc/
├── SKILL.md                          392 行   ← 模型的执行指令（主文件）
├── README.md                         本文件   ← 给人看的说明
├── references/
│   ├── address-map.md                582 行   ← 定地址时查
│   ├── function-library.md          1117 行   ← 写具体功能时查（最厚的一份）
│   ├── element-grammar.md            383 行   ← 写 add_rung 时查字段
│   ├── patterns.md                   300 行   ← 拿到需求先找现成结构
│   ├── project-conventions.md        258 行   ← 动手前看「真机都怎么做」
│   ├── comment-encoding.md           167 行   ← 写注释前查编码
│   └── lad-format.md                 160 行   ← 排错时看字节结构
├── scripts/
│   ├── check_lad.py                  249 行   ← 文件被改坏了，用它定位
│   └── zh_tw.py                      224 行   ← 注释转繁体 / 查能否编码
└── assets/
    └── build_program.py              271 行   ← MCP 不可用时的离线退路
```

### 各文件读到什么程度

| 文件 | 什么时候读 | 读到什么程度 |
|---|---|---|
| `SKILL.md` | 每次都读 | 全文。地址三分法、硬约束、注释三层、三层验证、21 条反模式 |
| `address-map.md` | 要写 `C` / `S` / `R` 时 | 按地址或关键词查，不用通读。602 条标准地址 + C/S 全表 + R 区权限 |
| `project-conventions.md` | 动手排地址之前 | §1 分区、§2 一点一义、§3 `R13`~`R18`、§5 选配、§6 注释模板、§8 被数据否掉的猜想 |
| `patterns.md` | 拿到需求的第一分钟 | 找有没有现成结构：自保持、锁存报警、单次动作、步序、互锁 |
| `function-library.md` | 写润滑/液压/排屑/刀库/M 码 | 先读 §0 骨架，再读对应那节；每节末尾「这一节的坑」必读 |
| `element-grammar.md` | 拼 `elements` 数组时 | 查字段名和取值范围，特别是并联嵌套、比较块、定时器精度 |
| `comment-encoding.md` | 写注释前 | 简繁对照表、两种注释的区别 |
| `lad-format.md` | 只在排错时 | 40 字节记录、连接位镜像、END 双格这些不变量 |

**新手上手顺序**：`SKILL.md` → `patterns.md`（看结构长什么样）→ `function-library.md` §0
（看一个功能由哪六件组成）→ 挑一个功能照推荐版抄一遍 → 出错再翻 `lad-format.md`。

## 3. 一次完整的使用过程

| 步 | 做什么 | 用什么 | 查哪份 |
|---|---|---|---|
| ① | 需求 → I/O 点位表 | 人工列，先列表再写图 | `project-conventions.md` §1/§2 |
| ② | 起空工程 | `new_ladder` | — |
| ③ | 写程序头（标题 / 履历 / 参数 / I/O 速查） | `add_comment_line` | `project-conventions.md` §6 |
| ④ | 一个功能一段，逐段写逻辑 | `add_rung` | `function-library.md` 对应节 |
| ⑤ | 每个地址挂短批注 + 长批注 | `set_comment` | `comment-encoding.md` |
| ⑥ | 清掉所有提示 | `validate` | 注意：**提示不拦保存** |
| ⑦ | 落盘 | `save` | — |
| ⑧ | 回读拓扑，逐条比对设计意图 | `read_ladder(format='text')` | — |
| ⑨ | 跑时序仿真 | 自己写断言 | `SKILL.md` §5 第 3 层 |

三处容易漏的：

- **`add_comment_line` 会占编辑器行号**。加 5 条程序头注释，后面所有梯形图整体下移 5 行。
  给人报行号必须用 `read_ladder` 的 `editor_row_start`，不能拿段序号当行号。
- **`validate` 通过 ≠ 能上机**。它返回纯文本提示，不分级、不阻断保存。真正的硬门槛是编辑器弹的框。
- **一行的 `elements` 按视觉从左到右给全**。凡有并联、多个输出、运算块，都不能用
  `condition`/`action` 那套简写。

## 4. 知识从哪来（依据分级）

技能里每条硬规则都标了出处，因为「手册说的」「编辑器实测的」「某台机器碰巧这么写的」
这三种东西的可信度完全不同：

| 级别 | 含义 | 例子 |
|---|---|---|
| **实测** | 反编译 `MLCEdit.exe` / 逐字节比对确认 | FEND 是双格、RTS 是单格；双线圈报错但不拦保存 |
| **手册** | 《PLC 编辑器操作手册》《CNC and PLC Interface》原文 | 8 类元件分工、`R81`~`R100` = 参数 3401~3420 |
| **真机惯例** | 四台实际机床的统计，可能是工艺使然 | 比较块 70~87% 是「等于常数」 |
| **推断** | 从机制推的，没单独验证 | 「双线圈只有后一处生效」（扫描语义推出） |
| **已被推翻** | 写进文档留档，防止再犯 | 「串联定时器不阻断」（现场纠正）、「报警必然自锁」 |

**标「真机惯例」和「推断」的，不能当成编辑器行为去断言。** 最贵的一次教训是：
早期自己造的样本末行 END 少写 4 字节，导致格式验证 100% 通过、实际生成全部错位。
所以验证基准只能来自**编辑器真实生成的文件**或真机文件。

### 样本：四台机器

| 标记 | 文件 | 大小 | 机型特征 |
|---|---|---|---|
| A | `cnc.lad` | 51.9 KB | 基础三轴，结构最简 |
| B | `cnc_1.lad`（= `cnc_2.lad`） | 54.2 KB | 润滑做法与 A 接近；排屑机借用了刀库门按键 |
| C | `M2I1653` | 83.0 KB | 刀塔三段动作 + 三段超时，结构最规整 |
| D | `M4R24179` | 80.5 KB | 逻辑最干净，参数注释欠账最多 |

`cnc_1.lad` 和 `cnc_2.lad` 是同一台的重复拷贝，统计时只算一台。

## 5. 覆盖到哪、没覆盖到哪

### 已经写透的

| 功能 | 章节 | 内容 |
|---|---|---|
| 润滑油泵 | §1 | 四家做法对比、开机预润滑、压力/液位双监视、`R55` 那个失效坑 |
| 液压站 | §2 | 五条现场启停规则、Y 轴液压刹车的三个连带问题、8 情形时序验证 |
| 排屑机 | §3.1~3.3 | 正转自保持 / 反转点动的理由、双向互锁、读请求位不读输出 |
| 冷却辅机 9 件 | §3.4 | 切削液、中心出水、侧冲、加工/对刀吹气、油冷机、补水泵、工作灯、安全门 |
| 刀库 / 刀塔 | §4 | 四种机构、伺服刀盘推荐版、三段动作 + 三段超时、刀号校验 |
| M 码 | §5 | 四家协议对比、D 机四旗标推荐版、M07~M43 映射、`S29`/`S30`/`S69` 握手 |

### 还没写透的

- **主轴**：定向、拉刀/松刀、刚性攻丝的气动时序，只有零散片段
- **气动夹紧**：夹紧/松开/自锁/掉气的保压判断，没成节
- **门锁与安全回路**：安全门、光栅、双通道，涉及法规，不能靠惯例推
- **多通道 / 双系统**：样本里没有
- **伺服刀塔的定位偏置**：`R103`~`R192` 刀号区怎么用，只到「不要动」这一层

要写这些功能，先在 `function-library.md` 里补一节，再动 `.lad`。

## 6. 质量保障

### 随包发布的

| 工具 | 查什么 | 怎么跑 |
|---|---|---|
| `scripts/check_lad.py` | 40 字节对齐、尾部 `00 fe`、每行 10 格、连接位镜像、END 双格、注释能否 cp950 解码 | `python check_lad.py 程序.lad [-v]` |
| `scripts/zh_tw.py` | 哪些简体字进不了 cp950 | `python zh_tw.py --check "文本"` |

两个都纯 stdlib，不依赖 MCP、不依赖仓库，拷到现场机器上也能用。

### 仓库侧的回归（不随技能包发布）

| 工具 | 查什么 |
|---|---|
| `tools/selftest.py` | 端到端：写 → 存 → 读 → 再存，字节必须完全相同 |
| `tools/verify_official.py` | 50 项官方基准（opcode 表、编码规则），对齐反编译结果 |
| `tools/verify_*.py` | 13 个专项：地址冲突、多线圈、并联、串联块、注释、报警 XML… |

文档示例也是被测的：`function-library.md` 里 9 个代码块、70 个元件组会逐个
解析 → 编码 → 回读，任何一个 typo（地址写成 `A331_S`、`norm` 写成 `"RS"`）都会当场炸出来。
液压 8 情形、排屑 4 情形另有逐扫描仿真。这四份校验脚本目前放在开发机
`_decomp/` 下，没有随包发布。

### 一个反直觉的结论

**结构往返能到 100%，几何逐字节一致率只有 778/1188。** 差的那部分是人工排版的列位
（留白、竖线位置），属正常。编辑器不做自动排版，人工摆放的空白重新生成时必然丢失——
这是原理性的，不是 bug。判断「生成得对不对」要看结构、时序、点位三样，不看字节全等。

## 7. 怎么装、怎么用

### 装

**不想碰命令行**：用仓库的 `installer/`（`python tools/make_installer.py` 打成的 zip），
解压后双击 `双击安装.bat`。它会检查 Python、跑自检、装技能包，并把 MCP 配置一起写进
`~/.workbuddy/mcp.json`，改动前都留备份。对方只需要再点一次「信任」。

**手动装**：

```bash
# 用户级（所有项目可用）
cp -r syntec-plc ~/.workbuddy/skills/
```

模型读到 `SKILL.md` 的 `description` 自动触发。触发词：新代 / SYNTEC / `.lad` / 梯形图 /
PLC 程序 / I/O 点位表，或具体功能名（润滑、刀库、排屑、液压站、气动夹紧、报警锁存…）。

### 配 MCP 工具（13 个）

```json
{
  "mcpServers": {
    "syntec-ladder": {
      "command": "python",
      "args": ["<绝对路径>/syntec-ladder-mcp-standalone.py"]
    }
  }
}
```

第一次配置不会自动生效，要到连接器管理页右上角的自定义入口点一次「信任」。

**MCP 没配好时**：机器上有本仓库 → 用 `assets/build_program.py` 直连源码离线生成；
两样都没有 → 让用户先装。**绝不允许手工拼字节绕过**——没有校验和，错位了不报错。

## 8. 维护约定

### 版本号

`SKILL.md` 头部的 `version` 是唯一版本源。改动规则：

- **加一节功能**（如补「气动夹紧」）→ 次版本 +1
- **改判断、改推荐写法**（如排屑反转从「应统一」改成「必须点动」）→ 次版本 +1
- **只修错别字 / 断链** → 补丁位 +1

### 加新功能时的顺序

1. 先在真机文件里找 2 份以上样本，按「四家做法」表列出差异
2. 标清哪一半**没在真机上验证过**（推荐版是融合，一定有没跑过的部分）
3. 写完把示例粘进 `add_rung` 跑一遍，确认能编码、能回读
4. 最后更新 `SKILL.md` §8 的参考表和本文件 §5 的覆盖表

### 三条不能破的

1. **不把样本特征当规范**。四台机器的统计只说明「这四台如此」，不说明「必须如此」。
   比较块用 `>` 还是 `=`、按钮取电平还是脉冲、报警锁不锁存，都由实际工艺定。
2. **不为了「一致」改掉不对称**。正转自保持、反转点动看着别扭，但那是两种用途。
   看到不对称先问「操作工松手以后，机器该不该还动」。
3. **每条硬规则都标依据**。没标的默认是推断，读的人有权不信。

## 9. 常见问题

**注释显示成问号** → 写了简体。先跑 `zh_tw.py` 再写，注意 `泵` 在 cp950 里有，不用转。

**报「双线圈」但能保存** → 编辑器只提示不拦。同一地址普通线圈只能 1 处，
置位/复位各只能 1 处。多个条件先并联再驱动那一个线圈，或改自保持回路。

**报「重复元件」** → 置位或复位写到第 2、3 处了。`LATCH`/`UNLATCH` 各只能 1 处。

**行号对不上** → `add_comment_line` 占编辑器行号。用 `read_ladder` 的
`editor_row_start`，不要用段序号。

**生成的文件编辑器打不开** → 先跑 `check_lad.py`。多数是末行 END 位置错，
或某个 8 字节块（定时器/比较/运算）按单格占了位。

**读回来和原文件字节不完全一致** → 正常。差的是人工排版列位，看结构对不对就行。
