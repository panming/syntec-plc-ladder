# 新代 CNC 梯形图编程

## 这个技能负责什么

把「机床要实现的工艺」翻译成新代 PLC 编辑器能直接打开、能上机的 `.lad` 文件。

**能做**：生成新程序、在已有程序上改逻辑、读别人的 `.lad` 反推意图、审查点位与互锁。

**不能做**：直接写控制器。工具只产出文件，上机流程永远是
`生成 → 编辑器打开核对 → 人工确认 → 拷到 DiskC\OpenCNC\Ladder\cnc.lad → 重启加载`。

---

## 0. 开工前先确认工具在位

需要的 MCP 工具（server 名 `syntec-ladder`，共 13 个）：

```
读：read_ladder  load_lad  dump_rungs  lookup_address  explain_rung
写：new_ladder   add_rung  set_comment  add_comment_line  save
查：validate     preview   explain_format
```

**每一步开工前先调 `explain_format`**。它返回当前版本的真实能力边界：已支持的元件 opcode、地址编码规则、已知限制（哪些功能块编码还没解出来）。不要凭这份文档的记忆去猜某个元件支不支持——以实际输出为准。

**MCP 不可用时**：

1. 先看本地是否已有仓库（`syntec-plc-ladder/`），有则用 `assets/build_program.py` 直连源码离线生成，见该文件头部注释。
2. 两样都没有 → 让用户先装：把 `syntec-ladder-mcp-standalone.py` 放进任意目录，MCP 配置登记 `{"command":"python","args":["<绝对路径>"]}`。
3. **绝不允许手工拼 `.lad` 字节来绕过这个问题**。`.lad` 没有校验和，字段错位后编辑器不报错，只会显示一张错的图——这种错到现场才炸。

## 1. 标准工作流

```
① 需求 → I/O 点位表          （先列表，再写图；不要边写边想）
② new_ladder                 起空工程
③ add_comment_line × N       程序头（标题 / 更新履历 / 参数 / I/O 速查 / 注意事项）
④ add_rung × N               逻辑，一个功能一段（结构查 function-library.md）
⑤ set_comment                每个地址都挂批注：短批注 + 长批注（ct=4，不占行）
⑥ validate                   提示清零才继续（它不阻断保存，见 §5）
⑦ save                       落盘
⑧ read_ladder(format='text') 回读拓扑，逐条比对设计意图
⑨ 三层验证                   见 §5
```

`add_rung` 有两条路，二选一：

- `condition` + `action`：适合简单的「条件串联 → 一个输出」。
- `elements`：按视觉从左到右给完整列表。**凡带并联、带运算块、一行多个输出，一律用这个**，`condition/action` 表达不了。

元件语法见 `references/element-grammar.md`（含 `parallel` 嵌套写法、定时器/计数器/比较块字段）。

## 2. 写第一行之前要定的四件事

### 2.1 地址怎么分

新代只有 8 类元件（手册 2.1），每类只干一件事。**先认元件，再挑地址**：

| 段 | 定义（手册原文） | 数量 | 谁能写 | 你该拿它做什么 |
|---|---|---|---|---|
| `I` | 实体输入接点（Input） | 依 I/O 卡 | 现场接线 | 读按钮、传感器 |
| `O` | 实体输出接点（Output） | 依 I/O 卡 | **阶梯程序** | 驱动继电器、接触器、指示灯 |
| `A` | **虚拟辅助接点（Auxiliary）** | `A0`~`A511` 共 512 | **阶梯程序** | **中间继电器 / 过程标志就放这里** |
| `C` | 由阶梯图发送指令给核心 | `C0`~`C511` 共 512 | **阶梯程序写**，核心读 | 只在「要控制器动作」时写，写完必须查手册 |
| `S` | 由核心传送系统状态给阶梯图 | `S0`~`S511` 共 512 | 核心写，**阶梯只读** | 只能当输入触点用 |
| `R` | 阶梯图与核心双向沟通 | `R0`~`R65535` | 按区段分权限 | **数据**：数值、参数、与核心交换的量 |
| `CT` | 虚拟辅助计数器 | `CT0`~`CT255` | 阶梯程序 | 计数 |
| `TM` | 虚拟辅助计时器 | `TM0`~`TM255` | 阶梯程序 | 延时 |

| 要存什么 | 用哪 | 说明 |
|---|---|---|
| 中间继电器、过程标志（打油请求、本次已建压…） | **`A0`~`A511`** | 512 点，只有 On/Off |
| 要跨断电记住的**数值** | `R193`~`R255`（避开 `R103~R192` 刀号） | R 的保持区 |
| **要用户能改的参数**（时长、间隔、次数、位置） | **`R81`~`R100`** | 对应系统参数 `3401`~`3420`，掉电保持，**阶梯只读** |

**只要有一个「操作员该能改的数」，就放 `R81`~`R100`，不要写死在程序里。**
这 20 个字是手册给「同一份梯形图适配不同机床」留的通道（原文：*R81~R100 MLC System
Parameter 由系统参数 No.3401 ~ No.3420 的 MLC 参数，以规划同一个 LADDER 可适用于不同的
机器上，如换刀*）。设定在**参数画面**做，程序只负责读：

```python
# R81 = 参数 3401 = 打油时长（0.1 秒）。定时器预设值直接指寄存器，不写常数
{"kind":"timer","name":"TM0","precision":"0.1s","source":"R","preset":"R81"}
```

`R50`~`R80` 也能读写，但**掉电不保持** —— 参数放那里，一断电就回零。所以三分法：
过程标志用 `A`，要给用户调的数用 `R81`~`R100`，要断电记住的累计值用 `R193`~`R255`。
`R81`~`R100` 方向是**只读**：写它 `validate` 会点名（提示级、不阻断保存），改参数请去参数画面 `3401`~`3420`。

**分段没有标准答案，别去规定「润滑必须占 `R81`~`R86`」。** 唯一要守的是
「同一功能的 `A` 位 / `R` 字连成一段、功能之间不重叠、段尾留空」——
这样现场查线和改参数时，一段连续地址就是一个功能。具体从哪个号开始随便，
`function-library.md` §0.1 / §0.2 给的表只是示例。

`R` 是 **32 位元寄存器**，可以存数值，也可以「拆开成位元使用」——所以 `R50.3` 语法上成立。
但那是在数据寄存器上抠一位用，不是它的设计用途。**内部标志用 `A`，`R` 留给数值。**

`syntec_address_db.check_write` 的口径：
- 写 `A` → 放行（`A512` 以上报错，编号只有 9 位）
- 写 `S` → error
- 写 `R81`~`R100` → error（系统参数传入区，只读；改参数去参数画面 `3401`~`3420`）
- 写 `R50.x` 这类「用户区数据寄存器取位」→ warn（能跑，建议改 `A`）
- 写 `R` 的只读区 / 无位存取区 → error

`S` 段**不是**中间继电器。它的 512 个点全部由核心写：`S0` 是「加工中」、`S1` 是「暂停中」、
`S6` 是「X 轴 Busy」。拿 `S0` 当自己的请求位，等于把「正在加工」当成「要打油」——
文件完全合法、编辑器不报错，上机才炸。`validate` 会点名写 `S` 的行为（提示级，不阻断保存，
所以别指望它拦；这条得靠你守住）。

`C` 段同理：写合法，但每一个都接到 CNC 内核上，随手拿 `C100` 当标志位可能就是在按急停。
**要接 CNC 信号，先 `lookup_address` 查清楚再写**。地址库收录 602 条标准地址，支持按地址查
（`C36`）也支持按中文/英文关键词反查（`倍率`、`原点`、`JOG`），给一个裸字（`A`、`S`、`R`）
会返回元件定义和点数 —— 另外 `references/address-map.md` 里有从厂商手册抽出的 C/S 全表
（各 512 点）和 R 分配表，查不到就看那张。

还有一条容易忽略的：**能取位的 R 只有 `R0`~`R639` 这一段，`R640` 起一律不行**。
`R640`~`R1023` 整片、`R1000`~`R1014` 那几个单点、`R1024`~`R1032`、以及 `R1033` 起的整片，
手册都标「位存取=否」。所以 `R1200.0` 这种写法编辑器不认，要位就用 `A` 段。
（`R256`~`R511` 曾经被这份文档误判成"保留区"——它是 `R103~R255` 的合并格延续，
可读可写可取位，只是掉电不保持。）

位元件编号上限 511：编码是 `(设备索引<<9)|(编号&0x1FF)`，`I600` 会被静默截断成 `I88`。`validate` 会点名越界，别忽略。

### 2.2 一个地址只能有一个线圈

判定口径（哪些是实测、哪些是推断，直接标在表里）：

| 线圈用法 | 同一地址允许几处 | 依据 |
|---|---|---|
| 普通输出 `NO`/`NC`/`RP`/`FP`（`=`） | **1 处** | ✅ **实测**：编辑器语法检查报「双线圈」，但**保存不拦**（仍提示「已保存」） |
| 置位 `LATCH`（`⊕`） | **最多 1 处** | ✅ **实测**：写到第三处即弹「重复元件」 |
| 复位 `UNLATCH`（`⊖`） | **最多 1 处** | ✅ **实测** |

「一置一复」是标准锁存写法，编辑器接受；**两处复位或两处置位就是重复元件**——
这一点很容易踩，因为逻辑上「故障停」「时长到停」两个出口看起来很自然。

两个条件要驱动同一个线圈时，**先并联，再驱动**：

> 别把两个概念混了：这一节说的是「**同一个地址**被几处驱动」。
> 「**一段里多个不同线圈**」是另一回事，完全允许，而且很常见 ——
> 把共享的条件写在前面，后面接一个 `parallel`，每个分支各以线圈结尾即可
> （见 `element-grammar.md` §6.1）。真机程序里 330 段有 97 段是这么写的。

```python
# 锁存 + 复位: 各只此一处，多个条件并联进去
[NO("I6"), COIL("A0", "LATCH")]                                  # 唯一置位
[PAR([NO("I5")], [NO("A4")]), COIL("A0", "UNLATCH")]             # 唯一复位(手动/故障并联)
```

自保持回路是更省的做法 —— 只有一个普通线圈，没有置位/复位：

```python
# A1 = (间隔到 ∥ A1 自锁) 且 无故障 且 时长未到
[PAR([TM_NO(1), NC("A4"), TM_NC(0)],      # 触发
     [NO("A1"),  NC("A4"), TM_NC(0)]),    # 自锁
 COIL("A1")]
```

禁用写法（会报重复元件）：

```python
[TM_NO(0), COIL("A1", "LATCH")]
[NO("A4"), COIL("A1", "UNLATCH")]     # ← 两处复位
[TM_NO(1), COIL("A1", "UNLATCH")]     # ← 第三处, 编辑器弹「重复元件」
```

`validate` 会把这两种都查出来：`重复元件`（置位/复位超一对）和 `双线圈`（普通输出线圈多处）。
注意它给的是**提示文本、不阻断保存**（见 §5 第 1 层）。

编辑器那边同样**不阻断**。实测：把 `O0` 挂两个普通线圈，语法检查报「双线圈」，
但保存照常提示「已保存」。所以**「能存下来」不等于「写对了」**——
带双线圈的程序能过保存这一关，问题要到上机才现形。
「只有一处生效」是扫描语义（后一处覆盖前一处）推出来的，没单独实测；
不管怎样，按「只能 1 处」写都不会错。

### 2.3 这一行是「持续」还是「单次」

- **持续型**：条件成立就一直动作（冷却泵跟着主轴转、夹紧保持）。用普通线圈。
- **单次型**：按一下就执行一个完整周期（手动打油、单次排屑、点动走一刀）。用「按钮置位 → 状态位保持 → 条件满足再复位」的三段式，**不要用按钮直接串线圈**，操作工按久了会过量。

**用上升沿还是电平，取决于按钮逻辑，不取决于习惯**：点动、计数、单次动作用上升沿脉冲；
长按才动作的（手动润滑、对刀点动、**排屑反转清屑**）用电平；**急停、超程、气压低这类安全信号必须用电平**，
做成脉冲等于把保护变成一次性的。

**不要把点动"统一"成自保持。** 正转自保持、反转点动看着不对称，但那是两种用途：
一个要连续排屑，一个要松手即停。判断标准是「操作工松手以后，机器该不该还动」。改动这类
不对称之前先问清用途，别按"一致性"改。

**点动就是点动，也别给它硬加定时器。** 反转清屑按住十秒以内是常规操作，程序去管它反而
碍事——清理到一半被断掉，人得先按停止再重来。防长时间堵转靠的是热继电器和操作规范，
不是 PLC 里加个超时。同理，正转该转多久就转多久，别自作主张加"连续运行 N 分钟自动停"。

### 2.4 `I0`~`I63` / `O0`~`O63` 一点一义，不要重复使用

**一个物理点只对应一个功能，只在一处进程序，需要它的地方一律走内部继电器。**

```python
# 输入: 进来就转 A 位, 后面只用 A 位 —— I0 在全场只出现这一次
[NO("I0"), COIL("A300")]                    # A300 = 手动松刀按钮
[NO("A300"), NC("A410"), COIL("A420")]      # 所有用到"手动松刀"的地方都读 A300

# 输出: 一个输出只由一个功能驱动
[NO("A420"), COIL("O0")]                    # O0 只在这里被驱动, 前面全是 A 位
```

现场调试时接线一定会改——按钮换常开/常闭、阀换点位、加个门开关。
如果 `I5` 散在 30 处梯形图里当条件，改一次接线要翻遍全程序；如果 `I5` 只在一处映射成 `A305`，
**改一行就完事**。这也是 `A300+n` / `A400+n` 两段镜像要留空的原因（见 `references/project-conventions.md` §1、§2）。

这条是**规范，不是现状**：真机里不少 `O` 点直接串 2~5 个条件驱动，没有 `A400` 那层。
别人的老程序不算错，但新写的按这条来。

## 3. 硬约束（违反会被**编辑器**拒掉；`validate` 只提示，拦不住）

| 约束 | 数值 | 后果 |
|---|---|---|
| 末行必须 END | `{kind:'end'}` | 编辑器打不开或提示程序不完整 |
| 一段的宽度 | **10 列** | 格式硬限（40 字节 / 4），超了没地方放 |
| 一段的行数 | 工具限 256 行 | **不是编辑器硬限**：实测 65 / 128 / 256 行都能正常打开，没探到天花板；真机最长 59 行 |
| 位元件编号 | 0..511 | 越界被静默截断成别的地址，`validate` 提示 |
| 定时器/计数器编号 | 0..255 | 编号只占 1 字节 |
| 定时器预设值 | 16 位，0..65535 | 1s 精度最大约 18 小时 |
| 同一地址线圈 | 置位、复位各 1 处；普通线圈 1 处 | 编辑器报「重复元件」/「双线圈」（**实测**）；双线圈实测**不拦保存** |
| 定时器/计数器 | 不重号 | 重号会互相踩预设值 |

**排版不要自己控制列位**。编辑器不做自动排版，人工摆放的留白和列位在重新生成时必然丢失——这是原理性的，不是 bug。生成时只管逻辑结构，「好不好看」交给编辑器。并联块会自动展开成多行、分支左对齐、汇合竖线只跨到最后分支所在行，这些规则已内置。

## 4. 注释：先转繁体再写

`.lad` 的注释块编码固定是 **cp950（Big5 繁体）**，与编辑器界面是简体还是繁体无关。简体字写进去会变成问号，且**不报错**。

```bash
python scripts/zh_tw.py --check "润滑油泵控制程序"    # 报出哪些字进不去 cp950
python scripts/zh_tw.py "润滑油泵控制程序"            # 转成 潤滑油泵控制程序
```

最常踩的一批：润→潤、压→壓、锁→鎖、电→電、动→動、开→開、关→關、过→過、继→繼、报→報、复→復、时→時、间→間、马→馬、达→達、轴→軸、检→檢、测→測、试→試、参→參、数→數、单→單、双→雙、选→選、择→擇、输→輸、统→統、机→機、设→設、备→備、线→線、铁→鐵、触→觸、点→點、启→啟、转→轉、换→換、确→確、认→認、态→態、断→斷、连→連、续→續、级→級、给→給、进→進、运→運、载→載、护→護。

`泵` 在 cp950 里有，不用转。

### 三层都要写满，别只写短批注

| 层 | 工具 | 写什么 |
|---|---|---|
| 元件短批注 | `set_comment(short=...)` | 这个点是什么，名词短语，4~8 字 |
| 元件长批注 | `set_comment(long=...)` | 完整一句：是什么 + 什么条件下动作 + 影响什么 |
| 功能段注释 | `add_comment_line(...)` | 每段功能前，四要素：输入点 / 输出点 / 主要功能 / 主要控制参数 |
| 程序头 | `add_comment_line(...)` | 机型、更新履历、I/O 速查、参数表、注意事项 |

```python
set_comment(addr="I8",  short="數刀信號", long="刀庫數刀近接開關, 遮斷=刀盤在定位點")
set_comment(addr="O12", short="刀盤推出", long="電磁閥 YV12, 1=推出; 未推出時 M6 停在 T 碼確認")

add_comment_line("; ===== 主軸吹氣：換刀後清潔刀柄 =====")
add_comment_line("; 輸入: C38(M.S.T完成) · A120(換刀完成)")
add_comment_line("; 輸出: O22(吹氣閥 YV22)")
add_comment_line("; 參數: TM3 = 2.0s (吹氣時長)")
add_comment_line("; 功能: 換刀完成後吹氣 2 秒, 手動模式下可由 AUX 强制吹氣")
```

**短批注只回答「这是什么」，长批注才回答「为什么会动 / 不动」。**
真机现状是短批注基本都填、长批注不到两成（A 机 52/290、D 机 75/445）——
那是老程序的欠账，不是标准。段上方的功能注释四台只有 26~31%，同样是要补的。

两个易错点：

1. **`add_comment_line` 写整行注释（ct=1）会占用编辑器的行号**。加 5 条程序头注释，后面所有梯形图行就整体后移 5 行。给用户报行号时必须用 `read_ladder` 返回的 `editor_row_start`，不要用段序号。
2. **`set_comment` 写的是元件批注（ct=4），挂在地址上、不占行**。真机文件里就是一条 `地址 \t短批注 \t长批注`，短批注和长批注存在同一条记录里，所以两个字段要一起填。这才是给 I/O 点做说明的正确工具。

编码细节与完整对照表见 `references/comment-encoding.md`；三层注释的写作要求和实例见
`references/project-conventions.md` §6。

## 5. 三层验证，一层都不能省

### 第 1 层：`validate` —— 工具侧的检查

查的是：末行无 END、地址越界、只有条件无输出、同址多线圈、定时器/计数器重号，
以及 `check_write` 判出的地址权限问题（写 `S`、写参数区、`R` 位存取越界…）。

**先认清它的实际强度**：`validate()` 返回的是一串**纯文本提示**，
**没有 error / warn 分级，也不会阻止 `save`**——`check_write` 内部确实分了 error 和 warn，
但 `validate` 把两者都抹平成一句话。所以：

- 「validate 通过」= 没发现这几类问题，**不等于**文件能上机；
- 出现提示也**不等于**存不下去，工具照存。
- 真正会拦住你的是**编辑器**，它弹的框才是硬门槛。

实操上仍然要求：把 validate 输出**逐条处理到空**，再进第 2 层。只是别指望它会替你挡住什么。

### 第 2 层：`read_ladder(format='text')` —— 拓扑自检

把存下来的文件重新读成文本梯形图，逐条比对是不是自己要的逻辑。

用 `text` 不要用 `json`/`both`：52 个分支的行 JSON 要 8147 字符，文本只要 1908 字符，而且文本能直接看出串并联对不对。`format='ladder'` 那种带 ╵╷ 的图形化渲染只适合人眼看单行，给模型读是噪音。

### 第 3 层：扫描级仿真 —— 时序

**格式对不等于逻辑对**。只有把时序跑一遍才知道「30 秒后会不会停」「故障时泵会不会真的断」。

按扫描周期逐拍推进，把预期写成断言而不是打印，改程序后能自动发现回归：

```python
assert pump_on_at == 1800.0, f"间隔应为 1800s，实际 {pump_on_at}"
assert pump_off_at == 1830.0
assert not any(alarm)          # 压力正常时不应报警
```

至少覆盖：正常周期、每个故障源单独触发、故障中途出现、手动与自动切换、复位条件不满足时清不掉。

### 字节级校验（可选，排错时很有用）

```bash
python scripts/check_lad.py 程序.lad          # 结构 + 连接位 + 注释可解码性
python scripts/check_lad.py 程序.lad -v       # 逐行打印
```

不依赖仓库、不依赖 MCP，纯 stdlib。查的是：40 字节对齐、尾部 `00 fe`、每行 10 格、END 是否双格、同格左右连接位是否镜像、注释能否按 cp950 解码。文件被别的工具改坏时用它定位。

## 6. 交付物

一份能用的程序交付四样，缺一样用户都得回来问：

1. **`.lad` 文件** —— 主交付物。
2. **说明文档 `.md`** —— I/O 点位表（地址/名称/电气约定）、参数表（哪个定时器是干嘛的、预设值怎么改）、接线注意事项（哪些点必须常闭接法）、以及**明确写出「未在真机验证」**。
3. **梯形图预览 `.txt`** —— `read_ladder` 的 text 输出，不开编辑器也能看。
4. **仿真结果** —— 跑了哪些场景、关键时间点是多少。

报告改动时给出**地址级的影响面**：改了哪几段、动到哪些输出、哪些原有互锁被绕过了。改别人的程序尤其要说清「我没有动哪些行」。

## 7. 反模式清单

写之前扫一眼，这几条都是踩过的：

- ❌ **拿 `C` / `S` / `R` 当中间继电器**。中间继电器只有 `A` 段（`A0`~`A511`）。`C` 是给核心下命令、`S` 是核心送来的状态（只读）、`R` 是数据寄存器。先 `lookup_address`，查不到就别用。
- ❌ **把用户该能改的参数写死在程序里**（`preset: 300`）。时长、间隔、次数、位置一律走 `R81`~`R100`（参数 `3401`~`3420`），定时器 `source:"R"` 直接指过去；也别放 `R50`~`R80`，那里掉电不保持。
- ❌ **以为 `R81`~`R100` 能写**。那是「参数 → 阶梯图」的单向传入区，写它 `validate` 会点名（提示级，不阻断保存，别指望它拦住你）；改参数是在参数画面改 `3401`~`3420`。
- ❌ **MCP 不可用时手搓字节**。宁可停下来让用户装工具。
- ❌ **拿自己手造的样本当标准答案**。这是本项目最贵的教训：早期自造样本末行 END 少写 4 字节，导致格式验证 100% 通过、实际生成全错位。验证基准只能来自**编辑器真实生成的文件**或真机文件。
- ❌ **用简体写注释**。不报错，只是显示成问号。
- ❌ **同一个 `I`/`O` 点在程序里到处用**。`I0`~`I63`、`O0`~`O63` 一点一义：输入进来就转 `A300+n`，输出由 `A400+n` 单点驱动。现场改一根线只改一行映射，否则要翻遍全程序。见 §2.4。
- ❌ **只填短批注，长批注留空**。短批注只够认出「这是什么」，说清「什么条件下动、影响什么」得靠长批注；功能段注释还要写清输入点/输出点/参数。
- ❌ **把样本特征当规范**。四台真机里比较块 70~87% 是「等于常数」、按钮基本都用上升沿、报警不一定自保——那是这四台机床的工艺恰好如此，不是写法规定。压力/位置/刀号范围判断该用 `>` `<` 就用；长按保持和安全信号必须电平；锁不锁存看设备要求。
- ❌ **同一个地址写多个线圈**。置位与复位各只能 1 处（多一处弹「重复元件」）；普通线圈也只能 1 处（报「双线圈」）。两类都实测过**会报警**；其中双线圈实测**保存不拦**（「重复元件」当时只确认了报警，没确认是否拦保存）。总之都不能拿「保存成功」当写对了。多个条件先并联再驱动那一个线圈，或改用自保持回路。
- ❌ **全程监视会瞬变的模拟量**。定量泵打油时分配器动作会让压力瞬掉，全程监视 → 正常打油也报警。改成「建立起一次就置标志位，本次不再管」。
- ❌ **复位条件只写「按了复位按钮」**。故障源没真消失就清得掉，等于把保护拆了。复位要串上「故障源已消失」：`[NO("I5"), NC("I2"), NO("I4"), COIL("A1","UNLATCH")]`。
- ❌ **相信「读回来一致就等于没问题」**。结构往返能到 100%，几何逐字节一致率只有 778/1188——差的那部分是人工排版的列位，属正常。结构对、时序对、点位对，才是真的对。
- ❌ **以为串联的定时器/运算块「不阻断」后面的元件**。手册 1-2.10 明写「定时器到达设定时间时，输出讯号为 ON」，1-2.7 明写「比较结果为真时，输出讯号为 ON」——它们是**条件**，不是直通线。`I100 → TM0 #10 → O10` 里 `O10` 的条件是 `I100·TM0`，串联本身就是「等它完成」。旧版文档说「串联等不到、要另接触点」是错的（2026-11-02 现场纠正）。
- ❌ **以为在梯形图里点亮报警位就有报警文字**。文字在 `AlarmPLC_CHS.xml`（按控制器语系还有 CHT / COM），由 `MLCEdit.exe` 单独维护；删掉程序逻辑不一定会删文字。`R40~R43` 是系统内定警报，文字在控制器里，根本不在 XML。
- ❌ **不做仿真就说「逻辑已验证」**。`validate` 通过只说明格式合法。
- ❌ **为了「一致」把点动改成自保持**。排屑反转、手动转刀盘点动天生就是「按住才动」，松手即停是安全要求。看到不对称先问用途，别按整齐划一去改。同理也别往点动里塞定时器——按住十秒是常规操作，程序断它反而碍事。
- ❌ **辅机（切削液 / 侧冲 / 中心出水 / 吹气 / 排屑泵）漏挂 `M09` 和 `M30`**。少串一个，结果就是 M09 停机后泵还在转、程序跑完没人关转到第二天。这两条必须串在每一件水气的输出链上（急停 `C36`、过载位同理）。
- ❌ **反过来把油冷机也串进 `M30` / 急停**。它是上面那条唯一的例外：主轴停了、急停按了，温度还得慢慢降，油冷跟着停就把热变形留在主轴和刀柄上，下个工件尺寸就飘。油冷只受自身报警和面板控制，另外给个启停延时（`TM66 R91`）防频繁启停。
- ❌ **过载信号直接进报警位**。热继电器常闭接点串在接触器回路上，变频器启动瞬间会抖开几个扫描周期，直接进报警会跳一闪而过的假报警。先过 2 秒定时器（`TM63 #2`），主电机更长。
- ❌ **只自锁不切断，或只切断不自锁**。报警自锁了但电机还在转 = 保护没生效；切断但没自锁 = 过载一消失故障记录就没了。两样都要：条件串在输出链上 + 报警位自锁到复位。
