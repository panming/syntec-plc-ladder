# 元件语法参考

`add_rung` 的 `elements` 参数：**按视觉从左到右**给完整元件列表。

```json
{"condition": [<触点或比较块>...], "action": [<线圈/定时器/运算块>...]}   // 简单行
{"elements": [<元件>...]}                                                // 复杂行(推荐)
```

`condition` 内部是串联、`action` 内部也是串联，从条件右侧接续。**凡是出现并联、一行多个输出、运算块，只能用 `elements`。**

---

## 1. 位元件

| 写法 | 字段 | 说明 |
|---|---|---|
| 触点 | `{"kind":"contact","norm":"NO"\|"NC","addr":"I132"}` | 常开 / 常闭 |
| 线圈 | `{"kind":"coil","norm":"NO"\|"NC"\|"RP"\|"FP"\|"LATCH"\|"UNLATCH","addr":"O10"}` | 见下表 |
| 定时器触点 | `{"kind":"contact_t","norm":"NO"\|"NC","index":27}` | `TM27`，编号 0..255 |
| 计数器触点 | `{"kind":"contact_c","norm":"NO"\|"NC","index":5}` | `CT5`，编号 0..255 |

线圈 `norm`：

| 值 | 含义 | 典型用途 |
|---|---|---|
| `NO` | 普通输出（随条件通断） | 驱动器件的唯一线圈 |
| `NC` | 常闭输出（条件成立时断开） | 很少用，注意与「常闭接线的输入点」区分 |
| `RP` | 正缘脉冲（条件上升沿导通一个扫描） | 触发单次动作、计数 |
| `FP` | 负缘脉冲（下降沿） | 下降沿触发 |
| `LATCH` | 置位（自保持，直到 UNLATCH） | 多入口启动、报警锁存 |
| `UNLATCH` | 复位 | 多出口停止 |

> 线圈用量：置位 `LATCH`、复位 `UNLATCH` 同一地址**各只能 1 处**（**实测**，多的那处弹「重复元件」）。
> 普通输出（`NO/NC/RP/FP`）同一地址也只能 1 处：编辑器语法检查报「**双线圈**」（**实测**），
> 但**不拦保存**——照常提示「已保存」。所以别拿「存下来了」当写对了的证据。
> 生效按扫描语义取最后一处（这一点没单独实测）。
> 多个置位/复位条件要先并联，再去驱动那唯一一个线圈；或者直接用自保持回路（一个普通线圈）。
> `validate` 会分别点名这两种（都是提示文本，不阻断保存）。

## 2. 定时器

```json
{"kind":"timer","name":"TM1","precision":"1s","source":"#","preset":1800}
{"kind":"timer","name":"TM2","precision":"0.1s","source":"R","preset":300}   // 预设取 R300
{"kind":"timer","name":"TM0","precision":"0.1s","source":"R","preset":"R81"} // 预设取参数 3401
```

| 字段 | 取值 |
|---|---|
| `name` | `TM0`..`TM255`（编号从字符串里解析，0..255） |
| `precision` | `1s` / `0.1s` / `0.01s` / `0.001s` |
| `source` | `#` = 预设常数（旧的 `K` 也接受，等价）；`R` = 预设由寄存器给（此时 `preset` 填**寄存器号**，`81` 和 `"R81"` 等价） |
| `preset` | 0..65535（16 位） |

`source:"R"` 最常见的用法就是指向**参数区** `R81`~`R100`（= 系统参数 `3401`~`3420`），
让操作员在参数画面改时间，而不是改程序。细节见 `patterns.md` §6.1。

**预设值换算**：实际时间 = `preset × 精度`

| 精度 | preset | 实际 | 最大可计时 |
|---|---|---|---|
| `1s` | 1800 | 30 分钟 | 65535 s ≈ 18.2 h |
| `1s` | 30 | 30 秒 | |
| `0.1s` | 300 | 30 秒 | ≈ 109 min |
| `0.1s` | 100 | 10 秒 | |
| `0.01s` | 100 | 1 秒 | ≈ 10.9 min |
| `0.001s` | 100 | 0.1 秒 | ≈ 65 s |

精度选择：**在够用的前提下选最粗的**。同一段时长，精度越细要的 preset 越大——
30 分钟（1800 秒）用 `1s` 要 1800，用 `0.1s` 要 18000，用到 `0.01s` 就是 180000，直接超 65535。
反过来 0.1 秒级动作别用 `1s`（最小分辨率就是 1 秒，根本达不到）。常用搭配：间隔/长延时 → `1s`；打油/润滑/动作时长 → `0.1s`；伺服/阀响应 → `0.01s`。

定时器占 **2 格（8 字节）**，参数区是 16 位小端，`[低, 高, 低, 0x80]`。

## 3. 计数器

```json
{"kind":"counter","name":"CT3","direction":"UP","source":"#","preset":50}
```

| 字段 | 取值 |
|---|---|
| `name` | `CT0`..`CT255` |
| `direction` | `UP` / `DOWN` / `RESET` / `RING_UP`（到值自动回零）/ `RING_DOWN` |
| `source` | `#` = 预设常数（旧写法 `K` 等价）；`R` = 寄存器给 |
| `preset` | 工具限制 `0..255`（**上限未经验证**，见下） |

> ⚠️ **编码形态是实测的，上限不是。**
> 定时器参数区是 `[低, 高, 低, 0x80]`（低字节重复一次），计数器是 `[低, 高, 00, 0x80]`
> （第三字节恒为 0，**不**重复低字节）——这一点在真机（2 个计数器：83、0）和
> 编辑器样本（6 个：50~55）里都成立。
> 但这 8 个样本的高字节**全都是 0**，值最大 83，**区分不了「只占 1 字节」和「16 位但高位为 0」**。
> 所以工具保守地把上限卡在 255 并给提示，这不代表编辑器只支持 255。
> 真要计 1000 次：先按 16 位写法生成 `[低, 高, 00, 0x80]`，在编辑器里打开确认预设值显示
> 1000 再上机；或者干脆用「CT 每 255 次进位 + `R` 寄存器做高位累加」绕开这个未知。

## 4. 运算 / 搬移 / 逻辑

```json
{"kind":"math","op":"ADD","A":"R200","B":"R201"}
{"kind":"move","op":"MOV","A":"R220","B":"R221"}
{"kind":"logic","op":"AND","A":"R230","B":"R231"}
```

| kind | 可用 op |
|---|---|
| `math` | `ADD` `SUB` `MUL` `DIV` `ADD_IMM` |
| `move` | `MOV` `MOV_IMM` |
| `logic` | `AND` `OR` `XOR` |

**语义是 `B = B op A`，不是 `B = A op B`**。这是最容易写反的地方：

```json
// R201 = R201 + R200
{"kind":"math","op":"ADD","A":"R200","B":"R201"}
// R221 = R220（把 A 搬到 B）
{"kind":"move","op":"MOV","A":"R220","B":"R221"}
// R201 = R201 + 5
{"kind":"math","op":"ADD_IMM","A":"#5","B":"R201"}
```

立即数一律写 `#N`。

## 5. 比较块（当触点用）

```json
{"kind":"compare","op":"GT","A":"R210","B":"R211"}      // R210 > R211
{"kind":"compare","op":"LTK","A":"#100","B":"R210"}     // 100 < R210，即 R210 > 100
```

| op | 含义 |
|---|---|
| `GT` | `A > B`（两边都是寄存器） |
| `LT` | `A < B` |
| `EQ` | `A = B` |
| `GTK` | `#A > B` |
| `LTK` | `#A < B` |
| `EQK` | `#A = B` |

**带 K 的三个 op，槽位是固定的：`A` 放常数、`B` 放寄存器。** 这不是随便定的，
是编辑器那边就这么认。写反了**不会报错**，但编辑器会把 `A` 里的地址号当常数、
`B` 里的常数当寄存器，变成 `#83 == R0` 这种恒假条件——程序能存、能打开、就是不成立。
（这一条是现场核对出来的：写入 `EQK A=R83 B=#0`，编辑器显示 `A=#83 B=R0`。）

所以「寄存器 与 常数 比」要按下面这张表翻一下方向：

| 想要 | 写法 | 编辑器里显示 |
|---|---|---|
| `R210 > 5` | `LTK` A=`#5` B=`R210` | `#5 < R210` |
| `R210 < 5` | `GTK` A=`#5` B=`R210` | `#5 > R210` |
| `R210 = 5` | `EQK` A=`#5` B=`R210` | `#5 == R210` |

嫌记不住就用 `cmp_reg_const`，按自然语义给，它自己翻：

```python
import syntec_model as M
M.cmp_reg_const("R210", ">", 5)    # -> LTK, A="#5", B="R210"
M.cmp_reg_const("R210", "<", 5)    # -> GTK, A="#5", B="R210"
M.cmp_reg_const("R210", "==", 5)   # -> EQK, A="#5", B="R210"
```

写成 `GTK A=R210 B=#5` 工具会直接拒绝保存并给出提示——这个错太安静，宁可拦住。

**没有 `GE` / `LE`**（编码表里只解出 GT/LT/EQ 各带 K 版这 6 个 opcode）。
而且比较块**本身不能取反**——它没有 `norm` 字段，所以「`LTK` 串在常闭逻辑里」这种写法
是写不出来的（整段也没有取反指令）。等价写法只有下面三种：

| 想要 | 写法 | 适用 |
|---|---|---|
| `A >= B`，结果驱动一个线圈 | `[LT(A,B)]` + `COIL(x,"NC")` | 线圈本身有常闭，可以直接用 |
| `A >= B`，当中间条件继续往后串 | `GT(A,B)` 与 `EQ(A,B)` **并联**成一个分支，再接后面的元件 | 通用，推荐 |
| `X >= 常数 N` | `cmp_reg_const(X, ">", N-1)`，即 `LTK(#N-1, X)` | 常数情形最省 |

```json
// A >= B 当中间条件: (A>B 或 A==B) 再串 Q
{"elements":[
  {"kind":"parallel","branches":[
     [{"kind":"compare","op":"GT","A":"R210","B":"R211"}],
     [{"kind":"compare","op":"EQ","A":"R210","B":"R211"}]]},
  {"kind":"contact","norm":"NO","addr":"A5"},
  {"kind":"coil","norm":"NO","addr":"O12"}]}
```

> 上表前两种写法已在工具侧实测：能生成、能回读、`check_lad.py` 零错误，
> 渲染出来是 `R210>R211 ╷ … =O12` / `R210==R211 ╵` 的标准并联。
> **编辑器打开的效果未验证**（并联块套比较块这种组合没在 14 个样本里出现过）。

比较块占 2 格，可以直接放在 `elements` 里当条件用：

```json
{"elements":[
  {"kind":"compare","op":"LTK","A":"#100","B":"R210"},   // 100 < R210
  {"kind":"coil","norm":"NO","addr":"O12"}]}
```

## 6. 并联

```json
{"kind":"parallel","branches":[[<分支1元件>...],[<分支2元件>...]]}
```

- 至少 2 个分支；每个分支内部是串联；分支里可以再嵌 `parallel`。
- 会自动展开成多行并自动排版（左对齐、汇合竖线只到最后分支所在行）。
- 每行 10 列是格式硬限；纵向行数工具限 256（**不是编辑器上限**：实测 65/128/256 行都能正常打开，没探到天花板）。

```json
// I100 串联 (I101 或 I102) 驱动 O200
{"elements":[
  {"kind":"contact","norm":"NO","addr":"I100"},
  {"kind":"parallel","branches":[
     [{"kind":"contact","norm":"NO","addr":"I101"}],
     [{"kind":"contact","norm":"NO","addr":"I102"}]]},
  {"kind":"coil","norm":"NO","addr":"O200"}]}
```

```json
// (I100 或 I101) 直接驱动 O200
{"elements":[
  {"kind":"parallel","branches":[
     [{"kind":"contact","norm":"NO","addr":"I100"}],
     [{"kind":"contact","norm":"NO","addr":"I101"}]]},
  {"kind":"coil","norm":"NO","addr":"O200"}]}
```

```json
// 自保持：启动按钮 或 自身常开 并联，再串停止常闭
{"elements":[
  {"kind":"parallel","branches":[
     [{"kind":"contact","norm":"NO","addr":"I0"}],
     [{"kind":"contact","norm":"NO","addr":"O0"}]]},
  {"kind":"contact","norm":"NC","addr":"I1"},
  {"kind":"coil","norm":"NO","addr":"O0"}]}
```

### 6.1 一段程序多个线圈

`elements` 本身就是串联列表，所以不需要新语法：**前缀放前面，分叉后的各支收进一个
`parallel`**。分支以线圈结尾即可，工具不会强行画汇合竖线。

```json
// 两个分支各带一个线圈（条件互不相干）
{"elements":[
  {"kind":"parallel","branches":[
     [{"kind":"contact","norm":"NO","addr":"I100"},
      {"kind":"coil","norm":"NO","addr":"O10"}],
     [{"kind":"contact","norm":"NO","addr":"I101"},
      {"kind":"coil","norm":"NO","addr":"O11"}]]}]}
```

```json
// 共享前缀 A9，再分叉
{"elements":[
  {"kind":"contact","norm":"NO","addr":"A9"},
  {"kind":"parallel","branches":[
     [{"kind":"contact","norm":"NC","addr":"A18"},
      {"kind":"coil","norm":"NO","addr":"C1"}],
     [{"kind":"contact","norm":"NO","addr":"A18"},
      {"kind":"coil","norm":"NO","addr":"A123"}]]}]}
```

**什么时候不能用这种写法**：真机程序里还有一类「共享一段 + 其中一个负载另有独立
通路」，例如 `A9` 只通往 `C1`、`I113` 却同时通往 `C1` 和 `R590.17`：

```
行0   A9 ──────────────────────────┬── =C1
行1   I113 ─ /A18 ─────────────────┘
行2        └── A18 ─────────────────── =R590.17
```

这种折不成树（`SERIES(A9, PARALLEL(...))` 会把 `A9` 误加到 `R590.17` 的条件上）。
只能用编辑器手画；工具读得出每个负载的条件（`explain_rung` / `read_ladder` 的
`loads` 字段），但保存时原样保留字节，不重排。

**判断依据**：问自己「每个分支是不是都从同一个点开始、各自完整走到线圈」。
是 → 用 `parallel`；否 → 不要硬拼，交给编辑器。

### 6.2 串联的功能块是条件，要等它导通

`TM51`、`R5174=R818`（MOVE）、比较块这类功能块串在通路中间时，**不是一条直通线**。
手册 1-2.10：「当定时器到达设定时间时，输出讯号为 ON，其相对的定时器接点亦为 ON。
当输入信号为 OFF 时，定时器停止计时，输出讯号为 OFF」；1-2.7：「当比较结果为成立
（真）时，输出讯号为 ON；不成立（假）时 OFF」。现场结论：
**只有定时器达到设定时间、或运算返回值为真时，才会导通后面的负载。**

所以「先计时 5 秒，再搬移」可以直接用串联写出来：

```json
{"elements":[
  {"kind":"contact","norm":"NO","addr":"A10"},
  {"kind":"timer","name":"TM51","preset":50},
  {"kind":"move","op":"MOV_IMM","A":"#1","B":"R5174"}]}
// A10 接通并保持 5 秒后, TM51 输出 ON, 才执行 R5174=1
// 路径枚举读作: R5174=1 ← A10·TM51
```

等价写法是用定时器触点（`contact_t`），两者都可行。**旧版文档说「串联等不到、
必须另接触点、后面每个扫描都执行」是错的**（2026-11-02 现场纠正）。

`review_ladder.py` 会把「上游串着功能块」的每一处列成一条说明性提示；
`explain_rung` 会把这些块算进下游负载的条件里。回归见
`tools/verify_series_blocks.py`（真值表）。

## 7. 流程控制

```json
{"kind":"jsr","label":"001"}      // 调用子程序
{"kind":"lab","label":"001"}      // 子程序入口，单独一行
{"kind":"rts"}                    // 子程序返回，单独一行
{"kind":"fend"}                   // 主程序结束（多程序段时用）
{"kind":"end"}                    // 程序结束 —— 最后一行必用
{"kind":"jmp","label":"002"}      // 跳转
{"kind":"msg","label":"001"}      // 信息显示
```

标签 ≤ 6 字节 ASCII，`JSR` 与 `LAB` 必须成对。
`END` / `FEND` 是**双格** 8 字节，只有 `RTS` 是**单格** 4 字节——这个区别由工具内部处理，不要手工拼。
（编辑器元件属性表里三者都标成 8 字节块，只有序列化时才分叉；这是本项目踩过最深的一个坑，见 `lad-format.md` §5。）

## 8. 原样字节

```json
{"kind":"raw","hex":"00 d0 00 00"}
```

用于读入时无法语义化的单元。**只在改动别人程序、必须原样保留某行时使用**，不要用它来「绕过」某个生成不了的功能。

## 9. 地址语法

| 形式 | 例子 | 说明 |
|---|---|---|
| 位元件 | `I132` `O10` `C36` `S16` `A302` | 字母 + 0..511 |
| 辅助接点 | `A0` | 虚拟辅助接点，本身就是一位 —— **内部标志就用这个** |
| 寄存器 | `R542` | 32 位元寄存器，存数值 |
| 寄存器位 | `R44.5` | 把寄存器拆开成位元用（报警区就是这么用的） |
| 立即数 | `#100` | 只在运算/比较里用 |

八类元件的方向完全不同，写之前先分清：

| 段 | 定义 | 能写吗 |
|---|---|---|
| `I` | 实体输入 | 不能，现场决定 |
| `O` | 实体输出 | 能，驱动现场 |
| `A` | 虚拟辅助接点 | 能 —— **中间继电器** |
| `C` | PLC → 核心（命令/握手） | 能，但每个点都接内核 |
| `S` | 核心 → PLC（状态/事件） | **不能，只读** |
| `R` | 双向数据寄存器 | 按区段（见 `address-map.md` §5） |
| `CT`/`TM` | 计数器 / 计时器 | 能，编号 0~255 |

`S` 段最容易写错：512 个点全是核心写的（`S0` 加工中、`S1` 暂停、`S6` X 轴 Busy、
`S32` Reset、`S33` NC Ready），拿它当中间继电器，`validate` 会点名。

内部标志只有一条路——**`A` 段**：`A0`~`A511` 共 512 点，随便用。
要跨断电记住的是**数值**，放 `R193`~`R255`（保持区，避开 `R103`~`R192` 刀号）。
`R50.x` 这种写法能跑（手册说 R 可以「拆开成位元使用」），但那是数据寄存器，不是继电器，
`validate` 会给一条提示建议改成 `A`。

`C` 段是 **CNC 系统接口**，不是通用中间继电器。写之前用 `lookup_address` 查：

```
lookup_address("C36")   → 紧急停止(PLC->CNC)
lookup_address("倍率")   → R15 主轴倍率 / R18 G00倍率 / R16 G01倍率 …
lookup_address("原点")   → C79 C80 C81 … 原点开关讯号旗标
lookup_address("JOG")    → C6 C8 C10 … 轴向 JOG(+)
```

查不到的地址说明地址库里没有这个标准功能——自己编一个 `C` 号很可能撞到真实功能上。
