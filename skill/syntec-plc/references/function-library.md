# 功能写法库：四台真机怎么写的，以及怎么写更好

`patterns.md` 讲的是「一个逻辑怎么拼」。这份讲的是**一个完整功能怎么落地**：
地址怎么分、状态位怎么排、参数放哪、报警怎么出、手自动怎么共存。

样本还是那四台（A `cnc.lad` 51.9KB、B `cnc_1.lad` 54.2KB、C `M2I1653` 83.0KB、D `M4R24179` 80.5KB）。
每条都标了**编辑器行号**，可以直接翻原文件对照。

**读法**：每节先列「四家做法」表，再给「推荐版」。推荐版是融合，不是照抄某一家；
每处改动都说明了为什么，以及**哪一半没在真机上验证过**。

## 0. 先看通用骨架：一个功能段由六件组成

四台程序里，凡是写得清楚的功能段，都是这六件按固定顺序排：

| # | 件 | 干什么 | 落点 |
|---|---|---|---|
| 1 | **入口** | 手动按键 / 自动命令 / M 码，转成一个请求位 | `I` 点经 `A300+n` 镜像 |
| 2 | **门** | 模式（`R13`）、使能、安全条件 | 串在请求位与状态位之间 |
| 3 | **状态位** | 就绪 / 动作中 / 完成，各一个 `A` 位 | `A2xx` 段（见 §0.2） |
| 4 | **输出** | 一个 `O` 点只由一个状态位驱动 | `A400+n` 镜像 → `O n` |
| 5 | **监视** | 超时、压力、到位、过载 | 定时器 + 比较，出 `A` 位 |
| 6 | **报警** | 监视结果 → `R44`~`R49` 的报警位 | 集中放末尾，一段一个 |

**顺序不能乱**：入口 → 门 → 状态 → 输出，中间不要插报警。报警全部挪到末尾集中，
现场查故障时从报警行往回找，路径最短。

**手动和自动共用同一个「执行核心」**，只在入口处分叉。这是 D 机刀盘做得最好的一点
（行 264 手动、行 289 自动，最后都汇到 `A315` 转刀盘），A 机 C 机也遵循同一思路。
手动另起一套输出，迟早会出现「手动能动、自动不动」或者两套逻辑打架。

### 0.1 参数先分好段，别让功能之间抢 `R81`~`R100`

`R81`~`R100` 一共 20 个字，对应参数 `3401`~`3420`。一份程序里往往有 4~6 个功能都要参数，
**开工先分好段再写**，不然写到第三个功能发现没位置了。

**没有任何规定说哪个功能必须放哪几个字。** 要守的只有三条：

1. **一个功能占一段连续的 `R`**，别东一个西一个。
2. **功能之间不交叉、不共用**，各占几个字由这个功能实际要几个参数决定，不是平均分。
3. **末尾留几个空位**。现场调试十有八九要加「延时」「次数」「门开关有无」这类小开关，
   临时拿 `R50`~`R80` 顶上，一断电就回零，第二天又得重设。

为什么强调「连续」而不是「固定位置」：操作工是在参数画面按 `3401`、`3402`… 往下翻的，
**连续几个参数属于同一个功能，他一眼能对上**；散着放，他就得拿批注一个个查，
或者干脆改错一个参数还以为是别的问题。至于这个功能从 `R85` 开始还是从 `R95` 开始，
只要不和别人咬住，怎么排都对。

下面这张表是**本库的排法，只是示例，不是规定**——你换一份程序，按自己功能的先后顺序
往下排就行，排完把段首段尾写进程序头注释：

| 参数 | 本库给谁 | 个数 |
|---|---|---|
| `R81`~`R86` | 润滑 | 6 |
| `R87`~`R90` | 液压 / 气动 | 4 |
| `R91`~`R92` | 冷却辅机（油冷启停延时、中心出水后吹气时长） | 2 |
| `R93`~`R96` | 刀库 / 刀塔 | 4 |
| `R97`~`R100` | 预留（现场补参数用） | 4 |

**参数号是顺序的，但含义是你自己定的**：`R81` 恒等于参数 `3401`，`R90` 恒等于 `3410`。
B 机就是按顺序往下排的（`R90` 压力延时 = 3410、`R91` 打油间隔 = 3411、`R92` 打油时间 = 3412）——
它把润滑排到了 `R90` 之后，占了本库留给冷却的两个字。**谁先写谁占**，不算错，
只是和上面的表对不上。
A 机的 `R93` 批注写着「系统参数 3407」，那是**批注写错了**（应为 3413）——
老程序的变量批注不能照抄，要对一遍参数号。

**换一台机台，`R81`~`R100` 的排法可能完全不同，所以拿别人的程序必须先读批注：**
D 机把 `R93`~`R98` 全拿去做了「报警接点常开/常闭」的形态开关
（行 1170-1186：`#0==R93` 刀臂、`#0==R94` 切削液、`#0==R95` 刀库、`#0==R98` 排屑），
同一台的 `R91` 又是油冷机启停延时（行 920）；A 机的油冷延时却放在 `R94`（行 498）。
**同一个字在不同机台上毫无关系。** 改别人的程序之前，先把 `R81`~`R100` 的批注整段读一遍；
遇到被占的，找个空档插进去，实在不够再新开一段（`R101` 起 = 参数 3421 起），
别硬挤进别人的参数里。

### 0.2 `A` 段先分段，别让两个功能抢同一个位

`A` 段不是一片自由内存，真机上它是**按用途切开的**（B 机文件头直接抄了这张表，
B/C 两台的变量批注逐条印证）：

| 段 | 用途 | 谁在用 |
|---|---|---|
| `A0`~`A99` | 面板 PLC、通用脉冲 | `A0` 开机脉冲、`^A` 按钮脉冲 |
| `A100`~`A199` | M 码 | 见 §5 |
| `A200`~`A299` | **PLC 功能性辅助接点 —— 功能状态位放这里** | 本库全部 |
| `A300`~`A399` | `A300+n` = `I n` 的镜像 | 每台机固定 |
| `A400`~`A499` | `A400+n` = `O n` 的镜像 | 每台机固定 |

这五个大区是硬约束：前三个是 SYNTEC 划的，后两个是镜像机制本身决定的。
**但 `A200`~`A299` 里面怎么切，没有任何规定**——手册不管，各家用各家的。

分法只有一个要求：**同一个功能的位连成一段，功能之间不重叠，段尾留一两个空位。**
因为这段地址唯一的作用是**现场查线**：翻到 `A255` 附近，上下十几行都是刀库，
不用翻批注就知道自己在哪一段；而把润滑的位散在 `A200`、`A243`、`A281` 三处，
排查一个压力开关能来回跳三次。

本库的切法（**示例，可以整段照抄，也可以按自己的功能顺序重排**）：

| 段 | 本库给谁 | 本库用到 |
|---|---|---|
| `A200`~`A219` | 润滑 | `A200`~`A211`、`A215` |
| `A220`~`A239` | 液压 | `A220`~`A234` |
| `A240`~`A244` | 排屑机（正转脉冲 / 反转按钮 / 停止 / 正转请求 / 反转请求） | `A240`~`A244` |
| `A245`~`A249` | 预留 | — |
| `A250`~`A259` | 刀库 / 刀塔 | `A250`~`A258` |
| `A260`~`A269` | 冷却辅机（切削液 / 中心出水 / 侧冲 / 吹气 / 补水泵） | `A260`~`A269` |
| `A270`~`A279` | M 码 | `A270`~`A275` |

润滑在 `A200` 还是 `A280`，机器跑起来一模一样。真正会出事的是两种：**同一功能的位散在几处**，
和**两个功能的段咬在一起**——后者加一个功能就得改一片地址，等于重画一遍图。

**每段留几个空位**，理由和 §0.1 一样：写到第三个功能才发现没位置，就得回头改前面所有地址。

## 1. 润滑油泵

### 1.1 四家做法

| | A（行 366-383） | B（行 192-205） | C（行 269-277） | D（行 1139-1172） |
|---|---|---|---|---|
| 触发 | 三路 `R611.1/.2/.3` → `TM11 #5` → `TM12 #5` → `vA5` | 同 A（`TM54/TM55`） | `TM3` 到时 → `TM4` 开始 | 两种模式：`R819=0` 固定间隔、`R819=1` 累计运行时间 |
| 间隔 | `CT1`，预设 `R91`（打油间隔） | 同 A | `TM3`，预设 `R91` | `TM85/86` 用 `R83`；累计模式用 `R204` 计数 |
| 时长 | `TM0`，预设 `R92` | `TM0`，预设 `R92` | `TM4`，预设 `R92` | `TM86`/`TM88`，预设 `R84` |
| 开机预润滑 | `A0 → A1`，时长 `R93` | `A0 → A4`，`TM8 #15` 固定 15 秒 | 无 | 无 |
| 手动打油 | 无（走 AUX6） | `I75`（AUX6）并到输出 | `I100`（F2）→ `A84`，`TM5 #10` | `I78` 并到 `R76.6` |
| 压力监视 | `TM14 R55`（=打油时间 −1 秒）超时 → `R44.9` | `TM9 R90`（压力延时）→ `R44.3` | 无 | `TM58 R816` → `R49.0`；液位 `I4` 独立 |
| 参数 | `R90`~`R93` | `R90`~`R92` | `R91`/`R92` | `R83`/`R84`/`R814`~`R816`/`R819` |

四家共同点：**泵输出由一个「打油中」状态位驱动，不是按钮直接串泵**；时长和间隔都是参数，
不写死；间隔与时长用两个定时器互锁（`TM3` 到 → `TM4` 计时 → `TM4` 到 → `TM3` 重来）。

### 1.2 各家的问题

- **A/B**：`R611.1/.2/.3` 三路触发没有任何注释说明是什么（推测是「系统上电 / 换刀后 /
  计数到」三路，但四台里只有这两台有）。压力监视套在 `TM14 R55` 上，
  而 `R55` 是 `R92 − 1` 算出来的——**打油时间改成 1 秒，监视时间就变 0，报警逻辑失效**。
  这是 A 机 2019-08-09 那条更新履历（「固定 6 秒改为打油时间减一秒」）留下的坑。
- **C**：只有一种模式，没有压力确认、没有油位，泵坏了不会报警。`A184` 是自保持，
  `I100`（F2）手动 10 秒——手动入口倒是有。
- **D**：结构最干净，压力（`I5`）和液位（`I4`）分开报，压力有独立延时；
  但**参数全部没有变量注释**（`R83`/`R84`/`R819` 的批注是空的），
  下一个人只能从代码反推 `R819` 是模式选择。这是典型的「逻辑写得好、注释欠账」。

### 1.3 推荐版

融合 D 的结构 + A/B 的开机预润滑 + C 的手动入口，参数重排成一组连续的：

| 参数 | 含义 | 单位 | 默认 |
|---|---|---|---|
| `R81` | 打油间隔 | 0.1 s | 18000（30 分） |
| `R82` | 打油时长 | 0.1 s | 300（30 秒） |
| `R83` | 打油模式：0 固定间隔 / 1 累计运行 | — | 0 |
| `R84` | 压力确认延时（打油开始后多久必须有压力） | 0.1 s | 100 |
| `R85` | 压力开关形态：0 常开 / 1 常闭 | — | 0 |
| `R86` | 开机预润滑时长 | 0.1 s | 150 |

| 状态位 | 含义 |
|---|---|
| `A200` | 打油请求（间隔到 / 手动 / 开机） |
| `A201` | 打油中 |
| `A202` | 本周期压力已建立过（瞬变量屏蔽） |
| `A203` | 压力确认超时（报警源） |
| `A204` | 油位低（报警源，独立） |

```python

{"elements": [
  {"kind":"parallel","branches":[
     [{"kind":"contact_t","norm":"NO","index":0}],        # TM0 = 间隔到
     [{"kind":"contact","norm":"NO","addr":"A210"}],      # 手动打油按钮(已取脉冲)
     [{"kind":"contact","norm":"NO","addr":"A211"}]       # 开机预润滑(见 ⑦)
  ]},
  {"kind":"contact","norm":"NC","addr":"A201"},           # 打油中不重入
  {"kind":"contact","norm":"NC","addr":"R44.2"},          # 油位低不启动
  {"kind":"contact","norm":"NC","addr":"R44.3"},          # 压力报警不复位
  {"kind":"coil","norm":"NO","addr":"A200"}
]}

# ② 打油中: 请求进来就起, 时长到(TM1)就停 —— 一个普通线圈自保持
{"elements": [
  {"kind":"parallel","branches":[
     [{"kind":"contact","norm":"NO","addr":"A200"}],
     [{"kind":"contact","norm":"NO","addr":"A201"},
      {"kind":"contact_t","norm":"NC","index":1}]         # TM1 = 打油时长
  ]},
  {"kind":"contact","norm":"NC","addr":"A204"},           # 油位低直接停
  {"kind":"coil","norm":"NO","addr":"A201"}
]}

# ③ 两个定时器互相打铃: 打油中计时长(TM1), 不打油时计间隔(TM0)
{"elements": [{"kind":"contact","norm":"NO","addr":"A201"},
              {"kind":"timer","name":"TM1","precision":"0.1s","source":"R","preset":"R82"}]}

              {"kind":"timer","name":"TM0","precision":"0.1s","source":"R","preset":"R81"}]}

# ④ 输出: 打油中 -> 泵(经 A400 镜像), 一个输出只有一个线圈
{"elements": [
  {"kind":"contact","norm":"NO","addr":"A201"},
  {"kind":"coil","norm":"NO","addr":"A401"}
]}
{"elements": [{"kind":"contact","norm":"NO","addr":"A401"},
              {"kind":"coil","norm":"NO","addr":"O1"}]}

# ⑤ 压力确认: 打油中 且 压力到 -> 记「本周期已建压」
#    A205 = 压力开关镜像(形态由 R85 决定, 见 patterns.md §2)
{"elements": [
  {"kind":"parallel","branches":[
     [{"kind":"contact","norm":"NO","addr":"A201"},
      {"kind":"contact","norm":"NO","addr":"A205"}],
     [{"kind":"contact","norm":"NO","addr":"A202"},
      {"kind":"contact","norm":"NO","addr":"A201"}]       # 自保持, 打油一停就清
  ]},
  {"kind":"coil","norm":"NO","addr":"A202"}
]}

# ⑥ 建压超时: 打油中 且 本周期还没建过压, 持续 R84 秒 -> 报警
{"elements": [
  {"kind":"contact","norm":"NO","addr":"A201"},
  {"kind":"contact","norm":"NC","addr":"A202"},
  {"kind":"timer","name":"TM2","precision":"0.1s","source":"R","preset":"R84"}
]}
{"elements": [{"kind":"contact_t","norm":"NO","index":2},
              {"kind":"coil","norm":"NO","addr":"A203"}]}

# ⑦ 开机预润滑: 上电给一个 R86 长的请求
{"elements": [{"kind":"contact","norm":"NO","addr":"A0"},
              {"kind":"timer","name":"TM3","precision":"0.1s","source":"R","preset":"R86"}]}
{"elements": [
  {"kind":"parallel","branches":[
     [{"kind":"contact","norm":"NO","addr":"A0"}],
     [{"kind":"contact","norm":"NO","addr":"A211"},
      {"kind":"contact_t","norm":"NC","index":3}]
  ]},
  {"kind":"coil","norm":"NO","addr":"A211"}

```

> ⑤ 的写法是「自保持 + 打油中」，不是「置位/复位」两个线圈 —— 后者在同一地址上
> 只能各有一处，一旦以后再加一个清除条件就得改结构。自保持永远只有一个线圈。

**为什么不用 A/B 的 `R55 = R92 − 1`**：打油时间调短时监视时间归零，报警失效。
独立给 `R84` 一个参数，操作员改时长不影响监视窗口。

### 1.4 这一节的坑

- **分配器动作会让压力瞬掉**，全程监视必然误报。只认「打油中建立过一次」。
- 压力开关接常开还是常闭由现场定，所以 `R85` 要有；真机 B 用 `#1==R88` 双向分支实现，
  写法见 `patterns.md` §2。
- **油位和压力必须分开报**。合成一个「润滑异常」，现场无法判断是没油还是泵坏了。
- 打油时长很短（<2 秒）时，压力来不及建立，`R84` 要留够余量；这个值要现场调。

## 2. 液压站

**四台真机都没有独立液压站**（C 机的 `A182` 是「液壓刀塔」，指刀塔夹紧用液压）。
但这一节的**启停规则是现场给定的**，不是推导的 —— 见 2.1。元件组合部分已编码验证。

### 2.1 启停规则（现场要求）

| 条 | 规则 |
|---|---|
| 1 | **开机默认关闭**。上电不自动起泵，`A220` 初值就是 0 |
| 2 | 面板「液压启动」按钮按下 → 起泵，**自锁**，松手继续转 |
| 3 | **液压过载** → 立即停泵 |
| 4 | **急停** → 停泵 |
| 5 | 例外：**装了 Y 轴液压刹车**时，急停**不**停泵 |

真值表：

| `R87`（Y 轴液压刹车） | 急停 `C36` | 泵 |
|---|---|---|
| 0 未装 | 无 | 按过启动按钮后运行，自锁 |
| 0 未装 | 有 | 立即停；急停松开后**不自己恢复**，要重新按启动 |
| 1 已装 | 无 | 同上 |
| 1 已装 | 有 | **继续运行**，保住刹车压力 |

> 这是「人来决定」的设计，跟 §1 润滑的「机器自己循环」正相反，不是笔误：
> 润滑泵几百瓦、缺一次打油最多磨损；液压站是几 kW 的泵，带上压以后主轴/卡盘/尾座
> 都在储能，**上电自动起泵等于在没人确认的情况下先把系统压起来**。规则 1 和 2 是一体的。

### 2.2 地址与参数

### 2.4 装了 Y 轴液压刹车时，三个连带问题

规则 5 只说「急停不停泵」，但液压不放手会让下面三处对不上：

1. **过载还是停泵 → 刹车可能松掉**。这一步取决于刹车类型，必须现场确认：
   - **液压释放、弹簧夹紧**（失压=夹紧）：过载停泵是安全的，甚至更好。
   - **液压夹紧**（失压=松开）：过载停泵等于把 Y 轴放掉。这种情况**不能立即停**，
     要么给 `R90` 填一个延时（先报警、让机械侧先动，再停泵），要么只报警不停泵、由人来停。
     光靠程序解决不了，机械上必须有蓄能器或掉电抱闸兜底。

   延时停泵的改法：把 ④ 里的「过载正常」换成「过载正常 **∥** 延时未到」。

   ```python
   # 过载延时计时: R90=0 时 TM12 当拍就到, 等价于立即停
   {"elements": [{"kind":"contact","norm":"NC","addr":"A231"},
                 {"kind":"timer","name":"TM12","precision":"1s","source":"R","preset":"R90"}]}

   # ④ 泵运行(带过载延时停)
   {"elements": [
     {"kind":"parallel","branches":[
        [{"kind":"contact","norm":"NO","addr":"A230"}],
        [{"kind":"contact","norm":"NO","addr":"A220"}]]},
     {"kind":"parallel","branches":[
        [{"kind":"contact","norm":"NO","addr":"A231"}],   # 过载正常
        [{"kind":"contact_t","norm":"NC","index":12}]]},  # 或: 过载了但还没到 R90
     {"kind":"contact","norm":"NC","addr":"A232"},
     {"kind":"coil","norm":"NO","addr":"A220"}
   ]}
   ```

   **推荐直接用这个版本**：`R90 = 0` 时它和 2.3 的原版等价（定时器预设 0 当拍就导通），
   现场按刹车类型填 0 或几十秒即可，程序不用改。两种刹车共用一份图纸，少一类变体。
2. **急停期间泵还在转，过载保护不能一起被禁**。所以 ④ 里过载串在急停**前面**，
   而不是把整段挂在 `NC(C36)` 下面 —— 后者在急停时会把过载也屏蔽掉，泵烧了没人知道。
3. **指示灯要分得出来**。`A233` → `O94` 这条不能省：急停按下后泵还在响、压力表还在，
   操作员第一反应是「急停坏了」。给一个「急停保压」指示，比在面板上贴张纸管用。

另外，规则 3 和 4 都是「停」，但**恢复方式不同**：

| 停的原因 | 恢复 |
|---|---|
| 过载 | 热继电器多数是手动复位型，**要先按热继上的复位杆**，再按启动按钮 |
| 急停（未装刹车） | 松开急停 → 按启动按钮。程序不自动恢复，这是规则 1/2 的直接结果 |

### 2.5 这一节的坑

1. **别用 `A0`（开机脉冲）去起泵**。有人为了「上电就有压力」加这一条，等于废掉规则 1，
   而且上电瞬间各轴位置还没确定，带压起泵有撞机风险。
2. **别拿压力开关自动启停**（§2.1 的前一版就是那么写的）。压力到了就停、掉了就起，
   接触器一小时能跳几百次；而且它绕过了「人来确认」这一步。
3. **卸荷是可选的，没有蓄能器就别做**。卸荷后蓄能器还能撑几下小动作；没有蓄能器时
   卸荷 = 动作瞬间掉压，刀塔夹紧会松。
4. **`R87` 别新开地址**。如果你们厂的标准已经把「Y 轴液压刹车」定在 `R8xx` 某一位，
   直接把 ③ 换成那一位（`{"kind":"contact","norm":"NO","addr":"R807.2"}` 或
   `EQK #1 == R80x`），不要另起一个参数 —— 同一台机上两个地方表示同一件事，
   迟早会不一致。
5. 建压超时、液位、油温、滤芯是**四个独立报警**，不要合成一个「液压故障」。
6. **装了 Y 刹车的机器，面板上最好留一个「液压停止」按钮**。这时急停已经不能停泵了，
   现场遇到油管爆裂、泵异响，只能靠它。加了停止按钮，2.3 的 ④ 要整段换掉 ——
   `A220` 不能在同一个程序里既有普通线圈又有 `SET`/`RST`，`validate` 不拦，但执行结果
   取决于扫描顺序，等于埋雷。换成这一对：

   ```python
   # ④-a 启动: 脉冲 -> SET(LATCH)。SET 本身就是自保持, 不用再串自锁支路
   {"elements": [{"kind":"contact","norm":"NO","addr":"A230"},
                 {"kind":"coil","norm":"LATCH","addr":"A220"}]}

   # ④-b 停止: 停止按钮 / 过载延时到 / 急停要求停泵, 三路任一 -> RST(UNLATCH)
   {"elements": [
     {"kind":"parallel","branches":[
        [{"kind":"contact","norm":"NO","addr":"A234"}],   # 停止按钮脉冲
        [{"kind":"contact_t","norm":"NO","index":12}],    # 过载延时到
        [{"kind":"contact","norm":"NO","addr":"A232"}]]}, # 急停要求停泵
     {"kind":"coil","norm":"UNLATCH","addr":"A220"}
   ]}
   ```

   > `norm` 只认这六个：`NO`(=)、`NC`(/)、`RP`(正缘)、`FP`(负缘)、`LATCH`(S)、
   > `UNLATCH`(R)。写 `"S"` / `"RS"` / `"SET"` 会直接抛 `KeyError`。停止按钮 `I101`
   > 要先取脉冲（`RP`）再进 ④-b，否则按住不放时每拍都在 RST。

   不想加按钮的话，**用 2.3 的 ④ 原版，不要混着改**。

> 启停规则来自现场要求；元件组合已编码验证（存盘 → 回读 → `validate` 零提示）。
> **时序未上机验证**，重点看两个：急停按下/松开时泵的状态，以及装了 Y 刹车后
> 过载停泵对 Y 轴的实际影响。

## 3. 排屑机与冷却辅机

排屑机本体只有「一个电机、两个方向」，难的是另外两件：**两个方向的操作方式怎么定**，
以及**它周边那圈水、气、泵怎么跟 M 码和急停协同**。后一件真机 D 做得最完整
（行 928-1075，一整片 9 个辅机），比单看本体值钱，所以单独放 §3.4。

### 3.1 两家做法

| | B（行 522-539） | D（行 1068-1075） |
|---|---|---|
| 按钮 | 借用刀库门开关按键（`I77`/`I78`，AUX6/AUX7）→ 脉冲 `^A77/^A78` | `I93` 正转 / `I99` 反转 / `I96` 停止 |
| 保持 | 自保持 `A231`/`A230` | 正转 `(A93∧/O93)∨(/A93∧O93)` 单按钮翻转；反转**电平** |
| 自动停 | `TM29 #10` / `TM30 #10`（10 秒后置 `A417`/`A418`） | 无 |
| 互锁 | `A503/A501` 使能、`/A78`、`/A77` | `/I99`、`/O7`、`/I96`、`/R46.11` |
| 过载 | `R45.2`/`R45.3`（分正反转两个） | `R46.11`（一个总过载） |

```

行 1070  A93  ╷/I99 /C36 /S32 /I96 /O7 /R46.11 ── ╷=O93
```

### 3.2 反转为什么必须是点动

D 机正转按一下就保持、反转必须按住不放。这个不对称很容易被当成「写法不统一」，
第一次看就判错过一次。现场确认：反转按钮是自复位点动，只用来清理缠屑。

这个定位是对的，三条理由：

- 反转不排屑，只是把卡在螺旋里的长屑退出来，正常加工永远用不到
- 清理时人要看着屑往哪走、手在机口附近，**松手即停是安全要求**，不是操作习惯
- 反转对减速机、链条都是反向受力，本来就该有人一直盯着

所以这不是不一致，是**两种用途给了两种操作方式**，而且必须保持不同。把它「统一」
成按一次自保持，等于把电机的控制权交给一个已经松开的按钮。

反转按住一般也就十秒以内，够把缠住的长屑退出来。**这个时间由操作工控制，程序不用管**——
加个定时器切断反而添乱：清理到一半被程序断掉，人还得先按停止再重来。

这一段真正要记住的是方法：**看真机时遇到"两边不对称"，先想是不是两种用途**，
别急着按整齐划一去改。真机上的不对称，多数是有人踩过坑之后留下的。

### 3.3 推荐版

形状照 D 走：正向「脉冲 + 自保持 + 停止按钮」，反向「电平点动」，两边都过输出侧互锁。
唯一的改动是把输出分成两级（请求位 `A243`/`A244` → 输出 `O6`/`O7`），

`M08/M09` 是行业惯例的配对，`M42/M43` 是机床厂自定义的，两套规矩在同一份程序里都成立。

#### 3.4.3 三件必须单独讲的

**油冷机既不挂 M30，也不挂急停。** 表里唯一一件没有 `/A130` 的、也没有 `/C36` 的就是它。
两个理由一样：主轴停了、急停按了，温度还是要慢慢降回来；油冷跟着停，热变形就留在主轴
和刀柄上，下一个工件一上来尺寸就飘。它只受自身报警（`R45.9`）和面板控制。

它的延时 `TM66 R91` 是防止「面板上顺手一按就启停」造成的频繁启停——油冷压缩机启停间隔
通常有硬性要求，参数 `R91` 就是给现场调这个的。

**切削液要能累计。** D 机在切削液那段挂了个 `=C101`，只在切削液开的时候计数。
批注没写用途，但从「只在开液时计」这个接法看，是给换液周期或浓度检查做提醒的。
这个做法值得抄：**液箱浓度失效是慢慢发生的，靠人记日子记不住**。

**过载信号进来之前要滤抖。** D 机的报警输入普遍串一个 2 秒定时器（`TM63 #2` 油冷、
`TM68 #2` 空调），A 机的切削液过载串 `TM9 #120`。热继电器常闭接点串在接触器回路上，
变频器一启动就瞬间抖开几个扫描周期，直接进报警位会跳「一闪而过」的报警，
现场根本抓不住。**2 秒是最低值，主电机建议更长。**

#### 3.4.4 四条通则

1. **一件辅机一个按钮，不要借**。B 机（行 522）把刀库门开关的 `I77`/`I78` 拿来当排屑正反转，
   面板上写着「刀库门开」，实际转的是排屑机。这种借法一旦机床配置变了（不装刀库门），
   排屑机就跟着没了。
2. **所有水气必须被 M09 和 M30 关掉**（`/A109`、`/A130`）。漏一个，就是下班后泵转一夜。
3. **急停关什么、不关什么，按后果分**。排屑、切削液、侧冲、中心出水全部串 `/C36`；
   **油冷机绝不能串**（D 机行 919 链上只有 `/TM66`）。急停时主轴不转，但温度还要慢慢降，
   停了就把热变形留在主轴和刀柄上。判断标准是**停掉之后会不会立刻伤人或烧件**，
   不会的就让它继续跑。
4. **过载报警要自锁，且要真切断输出**。A 机的 `R44.6` 用 `R44.6 /S32 /C36` 自保持，
   D 机的 `/R46.11` 直接串在输出段。**只做其中一个都不够**：只自锁不切断，
   报警挂着电机还在转；只切断不自锁，过载一恢复故障记录就消失了，第二天查不到。

### 3.5 这一节的坑

- **正反转必须互锁两次**：按对方按钮无效（`/A244`、`/A241`）+ 输出侧串对方线圈（`/O6`、`/O7`）。
  只做一个，接触器卡死时照样短路。
- **反转点动不要"统一"成正转那样的自保持**。它的用途是清理缠屑，松手即停是安全要求，
  不是操作习惯不一致。按住十秒以内是常规操作，**程序不用给它加定时器**——加到一半被程序
  断掉，人还得先按停止再重来，反而碍事。
- 过载串在**两个方向都要**（D 只串了一个总过载位 `R46.11`，是对的；
  B 分成 `R45.2`/`R45.3` 两个，容易漏掉一个方向）。
- 排屑机经常和「侧冲」「切削液」共用按钮（D 的 `I93` 同时驱动 `O6` 和 `O93`）。
  共用可以，但**在注释里写清「按正转哪个阀也跟着开」**，否则现场查线会以为接错。
- **自保持读自己的请求位（`A243`），输出侧互锁读对方的输出（`/O7`）**。一个读请求位、
  一个读输出，是有意的：请求位判断"我要不要转"，输出位判断"对方接触器真的没吸合"。
- B 机的 10 秒定时器输出 `A417`/`A418` 没有串回自保持链，**停不停取决于这两个位在下游怎么用**，
  光看这段代码看不出来。这种「停止条件写在旁边、不串在链上」的写法，下一个接手的人只能猜。
- 反转按钮不取脉冲，直接用电平——**但必须确认它是自复位按钮**。如果是自锁式（按下卡住），
  这套逻辑就变成"按一下开始反转、再按一下才停"。

### 4.2 D 机最值得学的三点

**① 數刀 + 定位双确认**（行 428-454）

```
行 428  I8 ────────────────────────────── ^A44      ← 數刀脈衝
行 444  I31 /…/ #1==R808 ──────────────── ^A43      ← 定位信號脈衝
行 445  A44 /…/ #1==R808 ──────────────── R74+#1    ← 數刀計數
行 446  A43 /…/ #1==R808 ──────────────── R75+#1    ← 定位計數
行 447  A300 TM138 R809 #1==R808 ╷R74>R75 ╷^A35     ← 兩個計數差 = 丟步
行 450  A35 /S32 /C36 ─────────────────── =R44.13  ← 刀庫定位異常
```

两个传感器（每刀一个脉冲的數刀 + 每转一圈一个的定位）分别计数，**差值不为 0 就报警**。
这比单靠「到位信号」可靠得多：皮带打滑、传感器漏检，都能抓出来。

**② 急停时能算出停在哪**（行 477-491）

刀盘被急停卡在两个刀套之间，`R50`（当前刀號）还是旧值。D 的做法是：转動中急停 →
用 `R64 = R50 + 1` / `R65 = R50 − 1` 推一个「最可能的刀套」，写进 `R51` 当目标，
下次启动先转回最近刀位，再继续。

**③ 大刀占双套**（行 239-246、302-333）

```
R72 = R89 + 1          總刀數
R202 = R88 * 2 + 1     大刀占用的刀套數
小刀起始刀號 = R202 + 1
```

换刀前先分三种情形（`A256` 目標在 1..R202、`A257` 大→小、`A258` 小→大），
各自把「交换的刀位」算进 `R63`/`R200`/`R201`，再做一次刀套定位。

### 4.3 C 机最值得学的一点：三段动作 + 三段超时

C 是液压（或伺服）刀塔，动作分三段，**每段一个超时报警**：

| 段 | 状态位 | 输出 | 超时 | 报警 |
|---|---|---|---|---|
| 推出 | `A21` | `O91`（推出阀） | `TM21` | `R44.10` 刀塔推出失败 |
| 旋转 | `A22` | `O9`/`O10`（正/反转） | `TM22` | `R44.11` 刀塔旋转失败 |
| 退回 | `A24` | `O92`（退回阀） | `TM24` | `R44.12` 刀塔退回失败 |

```
行 605  A21 TM21 ╷ ───────────────────── ╷=A26      ← 推出超时
        A21 C36  │                       ╵=R44.10
        A26 /A20 ╵
```

这个结构直接解释了「刀盤未推出」误报：**只要 `A20`（换刀完成）没来，`A26` 一旦被
`TM21` 置起就一直锁着**，直到复位。如果推出到位信号抖动或者 `TM21` 给得太短，
就会出现「实际推出了、还是报没推出」。C 机正是你之前遇到的那台。

```python
# ⑤ 自动: T 碼跟当前刀號不同 -> 起换刀
#    没有 NE 比较块, "不相等"必须写成 GT ∥ LT 两个分支
{"elements": [
  {"kind":"contact","norm":"NO","addr":"A250"},
  {"kind":"parallel","branches":[
     [{"kind":"compare","op":"EQK","A":"#2","B":"R13"}],  # 自动
     [{"kind":"compare","op":"EQK","A":"#3","B":"R13"}]   # MDI
  ]},
  {"kind":"contact","norm":"NO","addr":"S69"},            # T 碼讀入
  {"kind":"parallel","branches":[
     [{"kind":"compare","op":"GT","A":"R3","B":"R50"}],   # T > 当前
     [{"kind":"compare","op":"LT","A":"R3","B":"R50"}]    # T < 当前
  ]},
  {"kind":"coil","norm":"NO","addr":"A251"}
]}
```

**必须补的四个监视**（B/A 有前两个，D 有前两个，C 有第三个）：

1. **转动超时**：`A251` 起 N 秒还没到 `R50 == R51` → 报警（皮带断、电机堵转）。
2. **定位双确认**：數刀计数 vs 定位计数，差值 ≠ 0 → 报警（D 的做法）。
3. **液压刀塔三段超时**：推出/旋转/退回各一个（C 的做法）。液压刀塔如果不做
   「推出失败」独立报警，就会出现「实际推出了、还是报没推出」——因为你没法区分
   「没推出」和「推出了但到位信号没回来」。
4. **换刀中禁止暂停/模式切换**：`R52 = 1` 时串进 `C1`（暂停）与模式判定。

### 4.5 这一节的坑

- **`Z` 轴必须在安全点之上才允许转刀盘**（A 机行 643-646：`A51` = Z 高于 `R90` 安全点，
  `A52` = Z 高于 `R91` 换刀点须保持定位）。这条不做，撞刀臂是迟早的事。
- **刀号 0 或超出总刀数**。D 机行 290 就是 `R72<R3` 或 `#0>R3` 时报 `R44.12`。
  没有这条，`T99` 会让刀盘一直转。
- **首次上电刀号未知**。B 机用「手动设定 1 号刀位」按钮（行 434-440），
  D 机用回零（行 456-475）。两种都要有，否则掉电重启后刀号是错的。
- 數刀传感器漏检一个脉冲，刀号就永久错位——**这就是为什么要双确认**。

## 5. M 码

### 5.1 四家协议对比

| | A（行 414-451） | B（行 425-431） | C（行 283-330） | D（行 114-160） |
|---|---|---|---|---|
| 读入 | `S29` → `A103`… 各 M 一个位 | `A270` → 各 M 一个位 | `S29` → `A10` | `S29` → `A270` |
| 执行中 | `A2` | `A270` | `A10` | `A270` |
| 完成 | `A4`（单一大 rung 收全部条件） | `A271` | `A9` | `A271` |
| 等待执行 | 无（隐含在 `A2`） | `A272` | 无 | `A272` |
| 等待结束 | 无 | `A273` | `A11`（等待转速） | `A273` |
| `C38` 来源 | `A2 · A40` | `A271 ∥ A40` | `A9 ∥ A20` | `A271 ∥ /S29`，再串 `A25` |

四家用的是**同一套握手**，区别只在旗标数量：

```
S29 (M Code Read)  ─┐
                    ├→ 置 M 位(A103…) ─→ 执行 ─→ 完成条件满足
R1  = M 碼號        ┘                                   │
                                                        ↓
                                              C38 (M.S.T Finish) → CNC 继续下一个 BLOCK
```

### 5.2 推荐版（D 的四旗标）

```python
# ① 执行中: S29 来且上一个已结束 -> A270
{"elements": [
  {"kind":"contact","norm":"NO","addr":"S29"},
  {"kind":"contact","norm":"NC","addr":"A271"},
  {"kind":"coil","norm":"NO","addr":"A270"}
]}

# ② 结束: 等待结束完成, 或急停/复位/上电
{"elements": [
  {"kind":"parallel","branches":[
     [{"kind":"contact","norm":"NO","addr":"A273"},
      {"kind":"contact","norm":"NO","addr":"A270"}],
     [{"kind":"contact","norm":"NO","addr":"A271"},
      {"kind":"contact","norm":"NC","addr":"A270"}],
     [{"kind":"contact","norm":"NO","addr":"C36"}],
     [{"kind":"contact","norm":"NO","addr":"S32"}],
     [{"kind":"contact","norm":"NO","addr":"A0"}]
  ]},
  {"kind":"coil","norm":"NO","addr":"A271"}
]}

# ③ 每个 M 一个位; 需要等轴/主轴走完的, 串 S30(分布结束)
{"elements": [
  {"kind":"contact","norm":"NO","addr":"A270"},
  {"kind":"contact","norm":"NO","addr":"S30"},            # 只有 M05/M19 这类才串
  {"kind":"compare","op":"EQK","A":"#5","B":"R1"},
  {"kind":"coil","norm":"NO","addr":"A105"}
]}
{"elements": [
  {"kind":"contact","norm":"NO","addr":"A270"},
  {"kind":"compare","op":"EQK","A":"#8","B":"R1"},
  {"kind":"coil","norm":"RP","addr":"A108"}               # 只做一个动作的用脉冲
]}

# ④ 等待执行: 所有 M 位都灭 -> A272
{"elements": [
  {"kind":"contact","norm":"NC","addr":"A103"},
  {"kind":"contact","norm":"NC","addr":"A105"},
  {"kind":"contact","norm":"NC","addr":"A108"},
  {"kind":"coil","norm":"NO","addr":"A272"}

# ⑤ 等待结束: 每个 M 的完成条件, 一个分支一条
{"elements": [
  {"kind":"parallel","branches":[
     [{"kind":"contact","norm":"NO","addr":"A105"},
      {"kind":"contact","norm":"NO","addr":"S61"}],       # M05 等主轴定位完成
     [{"kind":"contact","norm":"NO","addr":"A108"},
      {"kind":"contact_t","norm":"NO","index":13}],       # M08 等冷却 15 秒
     [{"kind":"contact","norm":"NO","addr":"A110"}]       # 无条件的直接算完成
  ]},
  {"kind":"contact","norm":"NO","addr":"A272"},
  {"kind":"coil","norm":"NO","addr":"A273"}
]}

# ⑥ 回 CNC
{"elements": [
  {"kind":"contact","norm":"NO","addr":"A271"},
  {"kind":"coil","norm":"NO","addr":"C38"}

```

### 5.3 关键点

1. **`C38` 必须「无条件也可能给」**。D 机写的是 `A271 ∥ /S29`（行 1216）：S29 已经消失
   （CNC 取消/单节中断）时也要给完成，否则 CNC 永远等在那一个 BLOCK。
   **这一条是四家里唯一做对的，其余三家在急停/复位边界上靠 `A0`/`S32` 兜底。**
2. **`S30` 不是可有可无的**。`S30` = Distribution End（轴分配结束），
   `M05`/`M19` 这类要等轴停稳再执行的，必须串 `S30`；否则 M 码和 G 码同动时会抢。
3. **一个 M 一个 `A` 位，不要复用**。A 机把 20 多个 M 塞进一个大 rung（行 433-451），
   逻辑没错，但现场加一个 M 码就要动那一整段，风险极高。
4. **等待执行 / 等待结束分开**（`A272`/`A273`）。只有一个「完成」位时，
   你在完成条件里写 `/A103 /A104 …` 会越写越长（A 机就是这样）。
5. **M 碼段注释里列一张表**：M 号 / 功能 / 完成条件 / 对应输出。现场查「M08 为什么不吹气」
   时，一眼能看到它等的是哪个条件。

### 5.4 这一节的坑

- `R1` 是 M 碼號，`R3` 是 T 碼號——**别写反**（D 机 `R3` 用于刀号，`R1` 用于 M）。
- `C38` 只在「M/S/T 完成」时给，和 `C0`（启动）、`C1`（暂停）不是一回事。
- 急停（`C36`）与复位（`S32`）期间**不要**给 `C38`，要让 CNC 侧自己复位。
- M 碼结束不等于动作完成。M08 是「开冷却」，动作立刻完成；M06 是「换刀」，
  要等刀库真到位。**完成条件必须写实际到位信号，不能写「命令已发出」**。

## 6. 功能之间的四条连线

单看每个功能都对，连起来还是可能出问题。这四条最容易漏：

1. **报警 → 各功能的门**。润滑报警要断润滑请求，但**不能断刀库**；电机过载只断那一台，
   不掐整机。别用一个总报警把所有功能一起停掉。
2. **模式 → 手动入口**。所有手动按钮都要串 `#4/#5/#6 == R13`，否则自动运行中按到按钮会动。
3. **换刀中 → 禁止其他动作**。`R52`/`R71` 这类「换刀中」旗标要串进暂停、单节、模式切换，
   不只是串进刀库自己的逻辑（A 机行 516-518 就是专门为这个写的两段）。
4. **急停 → 状态复位**。`C36` 要能把「打油中」「刀库动作中」「换刀中」全部清掉，
   而不是只停输出。否则急停恢复后，程序以为自己还在动作中。

## 7. 怎么用这份文档

1. 接到新机床需求，先按 §0 列出六件，把地址表填满（`I`/`O` 一点一义，`A300+n`/`A400+n` 留镜像）。
2. 按 §0.1 把 `R81`~`R100` 分段，先留 4 个空的。
3. 对应功能来这一份找推荐版，抄结构、改地址、改参数。
4. 报警集中末尾，一段一个，注释写清「什么条件下报、怎么复位」。
5. 按 `SKILL.md` §5 三层验证：`validate` → 回读拓扑 → 扫描级仿真。

改动别人的程序前，先跑 `tools/review_ladder.py`，确认改的是哪几段、动到哪些输出。
