# 批注编码与简繁转换

## 一句话结论

`.lad` 的注释块**固定用 cp950（Big5 繁体）**，与编辑器界面是简体还是繁体无关。
简体字写进去**不会报错**，只会在编辑器里显示成问号或整段被吞。
**写注释前先过一遍 `scripts/zh_tw.py`。**

---

## 1. 两种注释，用途完全不同

| 工具 | ct | 占编辑器行号 | 用途 |
|---|---|---|---|
| `add_comment_line` | 1 | **占** | 程序头：标题、参数说明、I/O 速查、注意事项 |
| `set_comment` | 4 | 不占 | 设备变量注释：挂在某个地址上，说明这个点是干什么的 |

`ct=3` 也是整行注释（另一种排版用），编辑器打开时同样占行；`ct=2` 是版本行。

**行号影响**：加了 5 条 `add_comment_line`，梯形图第一行就从编辑器第 6 行开始。
向用户报行号时用 `read_ladder` 返回的 `editor_row_start`，不要用内部段序号。

## 2. 记录布局（写编码器时才需要）

一个注释块由 1 条首记录 + 若干条续记录组成，每条仍是 40 字节。

```
首记录:  [00] [00] [字节数] [ct] [00 00] 从 byte6 起，每 4 字节槽存 2 字节，9 槽 = 18B
续记录:  [00] [00] 从 byte2 起，每 4 字节槽存 2 字节，10 槽 = 20B
```

具体槽位：

```
首记录  byte:  0  1  2   3   4  5 |  6  7 | 10 11 | 14 15 | ... | 38 39
               00 00 字节 ct  00 00|  c0 c1|  c2 c3|  c4 c5|     | c16 c17

续记录  byte:  0  1 |  2  3 |  6  7 | 10 11 | ... | 38 39
               00 00 |  c0 c1|  c2 c3|  c4 c5|     | c18 c19
```

三个容易写错的地方：

1. **`byte2` 存的是字节数，不是字符数**。一个汉字 2 字节，`"潤滑"` 的 `byte2` 是 4。
2. **首记录和续记录的字符起点不对称**：首记录从 `byte6` 起，续记录从 `byte2` 起。
   照抄首记录的写法处理续记录，会整体错一位。
3. **每个 4 字节槽只用前 2 字节**，后 2 字节（byte4-5 / byte8-9 …）恒为 0。

条数算法：`ceil(字节数 / 单条容量)`，首条容量 18 字节、后续每条 20 字节。
单条注释上限 255 字节（`byte2` 只有 1 字节），约 127 个汉字。

> 这段规则是从反编译的编辑器逻辑（`syntec_re.parse_raw`）反推的，写编码器后用
> **真机文件逐字节验证**：`cnc.lad` 657 条、`cnc_1.lad` 950 条，全部重现，0 差异。

## 3. 简繁转换

```bash
python scripts/zh_tw.py "润滑油泵控制程序"          # -> 潤滑油泵控制程序
python scripts/zh_tw.py --check "润滑油泵"           # 检查哪些字进不去 cp950
python scripts/zh_tw.py --audit                     # 自查映射表
python scripts/zh_tw.py --file notes.txt            # 转换并写回文件
```

作为模块用：

```python
from zh_tw import to_tw, unencodable
text = to_tw("自动周期打油 间隔30分")     # '自動週期打油 間隔30分'
assert not unencodable(text)              # 全都进得去 cp950
```

`--check` 有不可编码字符时退出码为 1，可以当 CI 门禁用：

```bash
python scripts/zh_tw.py --check "$(cat 注释草稿.txt)" || echo "注释里有字进不去 cp950"
```

### 转换是有边界的

映射表 280 项：256 项是**编码必需**（源字形在 cp950 里根本不存在，不转就是乱码），
24 项是**风格转换**（源字形在 cp950 里有，只是台湾习惯用另一个写法）。

其中 8 项有语义歧义，批量转换后要人眼扫一遍：

| 字 | 风险 |
|---|---|
| 里 → 裡 | 「公里」作为长度单位应保留「里」，转成「公裡」是错的 |
| 复 → 復 | 「復」表再/返回（**復位 ✓**）；「複」表重复（複製），不要一律转復 |
| 准 → 準 | 「準」表标准（校準 ✓）；「准」表准许 |
| 台 → 臺 | 「臺」表台座/台湾；工作台→工作臺 可接受，机台编号宜保留 |
| 于 → 於 | 「於」表在；姓氏「于」不能转 |
| 并 → 並 | 「並」表并且；「合併」用併 |
| 云 → 雲 | 「雲」表云；作「说」时不能转（工控语境罕见） |
| 后 → 後 | 「後」表之后；「皇后」用后（工控语境罕见） |

## 5. 自查：怎么确认注释写对了

**唯一可靠的验证方式是把文件读回来，把注释解码出来再重新编码，和原字节逐字节比对。**

```bash
python scripts/check_lad.py 程序.lad -v      # 逐条打印注释，顺带查编码
```

```python
# 用仓库的 syntec_re 反向验证
import syntec_re as R
raw = R.parse_raw(open("程序.lad", "rb").read())
for kind, payload, rec, ct in raw:
    if kind != "logic":
        print(ct, R.text_of(payload))
```

出现 `[WARN] 注释不是合法 cp950` 要分两种情况：

- **自己新写的程序** → 真问题，说明有字没转繁体，回去改。
- **别人的真机文件** → 大概率是历史遗留（早年 GBK 输入法混进了 Big5 字段），
  编辑器里显示乱码但不影响运行，不用动它。
