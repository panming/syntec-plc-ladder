# 现场约定：真机都这么做、手册里没写

新代手册讲元件、讲语法、讲能存多少点，**不讲「程序该怎么组织」**。
下面这些是从四台不同机器的真机程序里读出来的默契，写程序时默认照做。

样本来源（四台不同的机器；`cnc_2.lad` 与 `cnc_1.lad` 是同一台的重复拷贝，不重复计。
真机程序属于设备资产，**不随本仓库发布**，这里只留可对照的特征）：

| 标记 | 来源 | 大小 | 特征 |
|---|---|---|---|
| A | `cnc.lad` | 51 922 | 基础三轴，结构最简 |
| B | `cnc_1.lad`（= `cnc_2.lad`） | 54 202 | 润滑做法与 A 接近；排屑借用刀库门按键 |
| C | `M2I1653` 控制器备份 | 83 042 | 刀塔三段动作 + 三段超时，结构最规整 |
| D | `M4R24179` 控制器备份 | 80 522 | 逻辑最干净，参数批注欠账最多 |

**依据分三档，写文档和答用户时都要带上**：

- **铁律** —— 四台全部一致，可以当规范执行。
- **多数** —— 三台一致，倾向这么做。
- **单机习惯** —— 一两台这样，不能当通则。

还有一档最容易被误判：**样本特征**。样本里没出现某种写法，只说明**这几台机床不需要**，
不说明那种写法是错的。第四节专门列了被数据否掉的猜想。

## 1. 地址分区

B 机的文件头里直接贴了一张分区表（这是程序注释，不是手册内容），C 机的变量注释逐条印证了它：

| 地址 | 用途 |
|---|---|
| `A0`~`A100` | 面板 PLC 使用 |
| `A101`~`A199` | M 码占用区 |
| `A200`~`A299` | PLC 功能性辅助接点 |
| `A300`~`A399` | 机床输入点（`I` 点）使用区域 |
| `A400`~`A499` | 机床输出点（`O` 点）使用区域 |

`A300+n` 就是 `I n` 的镜像、`A400+n` 就是 `O n` 的镜像（B 机：`A300` 手动松刀 ↔ `I0`，
`A400` 主轴运转 ↔ `O0`，一路对到 `A431`）。**所以 A 段不是随便用的中间继电器池，
300/400 两个百位已经被 IO 镜像占了。**

I/O 本体也分区，四台一致：

| 范围 | 用途 |
|---|---|
| `I0`~`I63` | 机床侧：急停、气压、过载、刀库原位、对刀仪 |
| `I64`~`I127` | 面板按键：轴方向、手轮、单节、模式、AUX |
| `O0`~`O63` | 机床执行元件：电磁阀、接触器 |
| `O64`~`O127` | 面板指示灯 |

B 机的变量注释按**每 16 点一组**写（「第一 I 板」「第二 I 板」），跟着 16 点 IO 板走。
现场加点时按板子编号找空位，比从头数快。

**`A200`~`A299` 内部怎么切没有规定，也不用去规定。** 手册不管，各家用各家的：
只要满足「同一个功能的位连成一段、功能之间不重叠、段尾留空」这三条，从哪开始都行。
润滑放 `A200` 和放 `A280`，机器跑起来一模一样；影响的是现场查线 —— 翻到 `A255` 上下十几行
都是刀库，不用翻批注就知道自己在哪一段。反过来说，把同一功能的位散在 `A200`/`A243`/`A281`
三处，或者两个功能的段咬在一起，才是真麻烦：加一个功能得改一片地址，等于重画一遍图。

`R81`~`R100` 同理，见 `function-library.md` §0.1。

## 2. `I0`~`I63` / `O0`~`O63` 一点一义，不要重复使用（铁律）

**一个物理点只对应一个功能，只在一处进程序，别的地方一律走内部继电器。**

```python
# 输入：进来就转 A 位，后面所有逻辑只用 A 位
[ NO("I0"),  COIL("A300") ]        # I0 = 手动松刀按钮, 全场只在这里出现
[ NO("A300"), ... ]                # 后面所有用到"手动松刀"的地方都读 A300

# 输出：一个输出只由一个功能驱动
[ ..., COIL("A400") ]              # A400 = 主轴运转请求
[ NO("A400"), COIL("O0") ]         # O0 只在这里被驱动
```

**为什么这么要求**：现场调试时程序还没定型，接线随时会改——某个按钮从常开改成常闭、
某个阀换到另一个点、加一个门开关。如果 `I5` 在 30 处梯形图里当条件用，
改一次接线就要翻遍全程序找 30 处；如果 `I5` 只在一处映射成 `A305`，
**改一行就完事**，剩下的逻辑一行不动。这也是 `A300+n` / `A400+n` 这两段镜像要留空的原因。

**现状要说清楚**：这条是规范，不是现有程序的普遍事实。四台里只有 A 机在面板区严格做到了
`I64` ↔ `O64` 一一对应（B 只对了 3 个、D 只对了 7 个）；不少 `O` 点是直接串 2~5 个条件驱动的，
没有 `A400` 这一层。别人的老程序这么写不算错，**但你新写的程序按这条来**。

## 3. `R13`~`R18` 是固定的（铁律，四台全用）

| 地址 | 含义 |
|---|---|
| `R13` | 模式：2 自动 / 3 MDI / 4 手动 / 5 寸动 / 6 手轮 / 7 原点 |
| `R14` | 手轮倍率 1 / 10 / 100 |
| `R15` | 主轴倍率 1~8 → 50%~120% |
| `R16` | 进给倍率 0~15 |
| `R17` | JOG 速度 |
| `R18` | 快移倍率 |

写法固定是**先把模式码写进 `R13`、后面只比较 `R13`**，不拿 `I` 点直接当条件：

```python
# 1) 采集: 原点模式按键 I67 按下 -> R13 = #7（全场只有这一段写 R13）
{"elements": [
  {"kind":"contact","addr":"I67","norm":"NO"},
  {"kind":"move","op":"MOV_IMM","A":"#7","B":"R13"}
]}

# 2) 使用: 后面所有判断都只比 R13
{"elements": [
  {"kind":"compare","op":"EQK","A":"#7","B":"R13"},
  {"kind":"coil","addr":"A320","norm":"NO"}
]}
```

好处是模式切换只有一个入口——加一个新模式只改第 1 段，几十处判断一行不动。
`R13` 只写一处，也顺带避开了「同一地址多线圈」。

## 4. 程序骨架：分章顺序四台几乎一样

1. **文件头**：机型名 + **更新履历**（日期 + 改了什么）
2. **`FEND` 之前只放硬实时信号**：跳过信号（对刀仪 → `C62`）、超程（→ `C55`）。
   A 机前面只有 4 段，D 机只有 3 段。这一段每个扫描周期先跑，不能被后面的长逻辑拖慢。
3. **开机脉冲** `^A0` → 初始化（C 机第一段就是）
4. 面板按键 → `A` 位脉冲（`I n` → `A(300+n)`）
5. 模式（`R13`）、倍率（`R14`~`R18`）
6. 安全互锁（Z 轴高于换刀点才许转刀盘）
7. 手动动作 → 自动动作（M 码 / T 码 → `A` 位 → 输出）
8. 主轴 / 刀库 / 冷却 / 润滑 / 三色灯
9. **报警集中在末尾，一段一个报警**
10. `END`
11. 子程序：`JSR "1"` → `END` → `LAB "1"` → 子程序 → `RTS`（只有 D 机用子程序，就是这个布局）

## 5. 选配用参数位分支，不改程序（铁律）

`#0==R8xx` / `#1==R8xx` 出现次数：A 44、B 23、C 72、D 50。

```
 I26      #0==R801   ╷ =C62     ← 参数=0 按常开接
 /I26     #1==R801   ╵          ← 参数=1 按常闭接
```

现场接常开还是常闭、有没有刀库门、有没有四轴，全用 `R8xx` 决定，**程序一个字不改**。
所以 `R8xx` 的注释全叫 MLC System Parameter，**别拿它当普通 `R` 用**。
（`R81`~`R100` 是用户可改的参数，`R801` 往上这一片是机床配置开关，两回事。）

## 6. 注释：三层都写满

用户的原话：**「注释最好每一个地方都写好，包括元件的长批注、短批注，
以及程序中每个功能的注释（包含输入点、输出点、主要实现功能、主要控制参数）。」**

### 6.1 第一层：元件批注（`ct=4`，不占行）

一条记录就是编辑器里那个「元件批注」对话框的两个输入框，真机文件里的原始字节是：

```
地址 \t短批注 \t长批注
```

例：`I8 \t數刀信號 \t`（长批注空）、`R808 \t程式鎖 \t程式鎖定用旗標`

| 字段 | 编辑器里 | 写什么 | 长度 |
|---|---|---|---|
| 短批注 | 元件旁 / 地址表 | 这个点是什么，**名词短语** | 4~8 字 |
| 长批注 | 批注列 / 交叉引用 | 完整说明：是什么 + 什么条件下动作 + 影响什么 | 一句，≤120 汉字 |

```python
set_comment(addr="I8",  short="數刀信號", long="刀庫數刀近接開關, 遮斷=刀盤在定位點")
set_comment(addr="O12", short="刀盤推出", long="電磁閥 YV12, 1=推出; 未推出時 M6 會停在 T 碼確認")
set_comment(addr="A305", short="手動松刀", long="面板手動松刀按鈕 I5 的鏡像脈衝, 只在手動/寸動模式有效")
```

**真机现状：短批注基本都有，长批注几乎没人填**——A 机 290 条变量注释里只有 52 条有长批注，
D 机 445 条里 75 条。这正是要补的地方：短批注只够让人认出「这是什么」，
长批注才回答「为什么会动 / 不动」。

### 6.2 第二层：功能段注释（`ct=1`，占一行）

**每段功能之前写，四要素缺一不可**：

| 要素 | 写法 |
|---|---|
| 输入点 | 触发这段的物理点或条件，写地址 |
| 输出点 | 这段的结果落在哪个 `O` / `A` |
| 主要实现功能 | 一句话说清这段干什么 |
| 主要控制参数 | 定时器/计数器编号、`R81`~`R100` 参数号、比较常数 |

模板：

```
; ===== 主軸吹氣：換刀後清潔刀柄 =====
; 輸入: C38(M.S.T完成) · A120(換刀完成)
; 輸出: O22(吹氣閥 YV22)
; 參數: TM3 = 2.0s (吹氣時長)
; 功能: 換刀完成後吹氣 2 秒, 手動模式下可由 AUX 强制吹氣
```

```python
add_comment_line("; ===== 主軸吹氣：換刀後清潔刀柄 =====")
add_comment_line("; 輸入: C38(M.S.T完成) · A120(換刀完成)")
add_comment_line("; 輸出: O22(吹氣閥 YV22)")
add_comment_line("; 參數: TM3 = 2.0s (吹氣時長)")
add_comment_line("; 功能: 換刀完成後吹氣 2 秒, 手動模式下可由 AUX 强制吹氣")
```

**别省**。四台真机只有 26~31% 的段正上方有标题注释——这是「现有程序做得不够」，
不是「这样就行」。

### 6.3 第三层：程序头

1. 机型 / 客户 / 程序版本
2. **更新履历**：`2026-11-04  修正刀盤未推出報警誤判` 这种，一行一次改动
3. I/O 速查（面板区、机床区各一张小表）
4. 参数表：`R81`~`R100` 每个对应哪个 `3401`~`3420`、干什么
5. 注意事项：哪些点必须常闭接法、哪些动作有互锁

### 6.4 编码

三层全部 **cp950（Big5 繁体）**，先过 `scripts/zh_tw.py`。简体写进去不报错，只是显示成问号。

## 7. 写法统计：能参考，别当规则

| 现象 | 数据 | 怎么用 |
|---|---|---|
| 一段一个线圈 | 81~84% 的段只有一个，平均 1.19~1.23 个 | 尽量；一地址多线圈才是硬错 |
| 同一地址不被两个线圈驱动 | 四台 0 处 | **铁律**，见 SKILL §2.2 |
| 很少用置位/复位 | A/B/D 各 0；C 只有 16 个置位、0 个复位 | 自保持回路优先，不是禁止 |
| 比较块以「等于常数」为主 | `EQK` 70~87%，`>`/`<` 合计不到 20% | **只是这几台不需要大小比较**，见 §8 |
| 自保回路 | 14~26% 的线圈条件含自身触点 | **看设备要求**，见 §8 |
| 段上方有标题注释 | 26~31% | 现状偏低，目标是全覆盖 |

## 8. 被数据否掉的猜想（重要，别当成规范）

这几条我一度当成「大家都这样」，逐台对数之后不成立。**样本没有 ≠ 不该有。**

| 猜想 | 实际 |
|---|---|
| 比较块只用「等于常数」 | ❌ 只是这四台的工艺恰好不需要大小比较。压力、位置、刀号范围判断必然要用 `>` `<`，该用就用 |
| 按钮一律上升沿（`Ixx → ^Axx`） | ❌ 取决于按钮逻辑。点动/计数/单次动作用上升沿；长按保持（如手动润滑、对刀点动）就该用电平；急停、超程这类安全信号必须电平，**用脉冲等于把保护做成一次性的** |
| 报警一定要自保 | ❌ 取决于设备要求。有的报警要锁到复位，有的必须随故障消失自动恢复（温度、压力这类过程量）。锁不锁由工艺定，不由习惯定 |
| `O` 点一律由 `A400+` 驱动 | ❌ 大部分 `O` 点是直接串 2~5 个条件的，只有 B 机 29/66 是单 `A` 位驱动 |
| `I`/`O` 同号同义 | ❌ 只有 A 机在面板区严格执行 `I64` ↔ `O64`，B 只有 3 个、D 只有 7 个 |

最后一条顺带说清：「IO 同号同义」指的是**同一个编号的输入点和输出点在功能上对应同一件事**
——比如 `I64` 是「X+ 按钮」、`O64` 就是「X+ 按钮灯」，`I70` 是「主轴正转按钮」、
`O70` 就是「主轴正转灯」。面板区按这个排，接线和查故障时不用来回对表。
它只是 A 机面板的一种排法，**不是全机通例，更不是必须**。
